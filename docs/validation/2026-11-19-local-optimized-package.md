# macOS 本地优化包和固定 Codex 配置

从干净的 `557c2933cb01fc1f9357f9688865b1624cc1102f` 构建 Hive Desktop 0.1.0 arm64。Rust 使用单个作业生成优化程序。生产运行时按锁文件离线部署。正常打包脚本下载 Node 22.23.3，并按官方清单验证归档 SHA-256。应用使用本地临时签名。

ZIP 解包、DMG 只读挂载和打包目录各自包含同一份应用。逐项核对 28,956 个文件、29 个链接和 2,709 个目录，文件摘要、可执行位、链接目标与目录结构一致。解包和挂载后的应用均通过严格签名验证。DMG 验证后已卸载。

## ZIP 解包后的原生真实流程

在独立项目建立两个工作树，给两个会话分别保存 Codex 配置 A、B 的 `r1` 及不同启动路径。项目根和两个工作树都有同名测试文件，内容各不相同。验收使用同一已有账号的官方 Codex CLI 0.169.0。两条请求分别由实际窗口的输入框和发送按钮提交。观测器在传输边界确认真实模型为 `openai/gpt-6.1-terra`，核对原生线程、执行目录和只读权限，每个会话最多放行一轮。

两个窗口结果各自准确返回工作树内的标记，独立读盘同时核对工具执行、回复、原始配置引用、会话 ID 和线程 ID。关闭再启动，从窗口切换两次，显示两条原回复，原生记录为同一线程的两次恢复。冷启动推理次数为零。两次应用退出均正常，桌面、Node 后台及已观测的 Codex 启动进程已回收。

首次夹具误把尚未提交首条消息的线程 ID 当成已持久字段。调整夹具后按首次真实回合的已保存身份核对。首次准备阶段没有触发推理，两轮真实请求均通过。此处验证单会话发送、固定配置切换和冷恢复。多 Agent 派单的既有独立证据见[多实例与 ACP 验收](2026-11-15-agent-profiles-acp.md)。
