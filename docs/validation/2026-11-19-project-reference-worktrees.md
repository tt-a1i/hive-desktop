# 项目文件引用与会话工作树

改动前，在 Alpha 工作树打开文件选择器，实际窗口列出了项目根目录独有的文件，无法从列表选择 Alpha 独有的文件。文件检索和抓取快照现在都传入同一个会话 ID，由后台解析执行目录。选择器显示当前目录，连接或打开会话的请求编号变化后会丢弃旧列表。普通会话仍按项目根目录查找。

桌面草稿保留引用的来源会话 ID、相对路径和 SHA-256。快照详情显示来源会话，检查源状态时按引用的来源解析执行目录。旧引用可以继续读取。

## macOS 实测

在本地签名的 arm64 应用中，用一个真实 Git 仓库及两个独立会话工作树进行操作。三个目录各有一个独有文件和一份内容不同的 `shared.txt`。

- 原生窗口分别在项目根会话、Alpha 和 Beta 中打开选择器。每个选择器只列出自己目录的独有文件。
- 通过三个选择器各添加一份 `shared.txt`。核对草稿、来源会话 ID、相对路径以及 Hive 私有副本的实际字节。三个 SHA-256 均不同，并与各自目录的内容相符。
- 移走 Alpha 的源文件，保持项目根及 Beta 的同名文件存在。窗口显示 Alpha 源文件缺失，预览仍显示保存时的 Alpha 内容。冷重开后，草稿、来源与摘要保持，原快照仍可预览。
- 旧版对照、修复版和冷重开均正常退出，收到后台关闭确认。此次没有发送消息或运行模型。

项目文件检索、引用与独立工作树专项通过。118 项 Rust 测试通过，另有一项子进程入口按设计忽略。macOS 包通过严格签名验证及 Node、PTY、Hive HTTP/SQLite 和退出冒烟。Windows x86_64 MSVC 交叉检查通过，原生窗口待复验。没有发布。

本地证据位于 `.artifacts/project-reference-worktrees-byiT5X/`，包含实际运行和冷启动日志、三份草稿及其私有副本、验收脚本和 `receipt.json`。

## Unicode 文件名

GPT-6.2 Sol 在真实 Git 工作树复现了 `Résumé 工作树.txt` 的搜索差异。旧版可用预组合的 `RÉSUMÉ` 找到文件，等价的分解形式返回空列表。`9969085` 用同一 Unicode 形式比较搜索词和路径，选择结果仍保留 Git 返回的原路径。
