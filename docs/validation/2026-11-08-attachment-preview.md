# 普通附件直接预览与紧凑草稿

## 使用变化

此前普通附件只能跳到文件管理器；在聊天中核对刚上传或历史中的文本，需要离开窗口。现在点击文件行打开已有只读预览，支持复制全文、键盘滚动、重新读取和文件管理器定位。普通文件草稿改成包含文件名、大小、移除按钮的紧凑横行，图片保留缩略图，避免文本附件占用图片卡片的高度。

这部分复用现有文件阅读组件，属于已确认的统一聊天体验完善，没有引入依赖、Agent 权限或新的协作规则。

## 读取边界

附件每次读取及定位都调用现有 `chat.attachments.path`，由原来的上传存储按工作区和附件 ID 校验并定位副本；不接收聊天正文给出的任意外部路径。项目工具/产物仍按原有工作区路径规则解析，没有通过放宽项目路径限制来访问附件目录。

附件标题明确说明是 Hive 上传副本，原文件删除不影响已保存副本。读取仍限普通 UTF-8 文本和 1 MiB，二进制、编码、缺失与超限错误明确展示；PDF 等不支持的内容仍可在文件管理器中显示。重新读取失败时保留上次内容并提示，成功后回顶部。不修改上传副本或历史记录。

## 验证

- `pnpm --filter @hive-desktop/runtime check:files`：现有真实 HTTP/SQLite 上传、原文件删除、跨工作区/无效/缺失 ID、真实编译后 RPC、关闭检查通过，无模型请求。
- `cargo test --locked --manifest-path apps/desktop/Cargo.toml file_viewer::tests`：现有实际文件 UTF-8/空/大小/二进制/路径边界检查通过。
- macOS 原生 GPUI 窗口：真实 Hive 上传文件、真实 Pi 历史记录和草稿恢复；点击草稿及历史附件、原始源文件已删除时仍可读、全文复制到实际剪贴板、Tab/PgDown 滚动、Escape 关闭、删除副本后保留旧内容并提示、恢复后重新读取、二进制错误与不同工作区 ID 拒绝。紧凑文件行移除附件后正文草稿仍保留。
- 共享预览回归：项目内文本可读，直接把附件副本绝对路径作为项目文件预览时仍拒绝。普通附件只通过校验过的 ID 入口访问副本。
- 生产入口 `cargo build --locked --manifest-path apps/desktop/Cargo.toml` 与 `cargo check --locked --manifest-path apps/desktop/Cargo.toml --target x86_64-pc-windows-msvc` 通过，构建后的应用没有夹具钩子。
- 浅色常规窗口与 760×583 浅/深色窗口检查。截图、夹具和日志位于 `.artifacts/attachment-preview/`。早期预置历史格式、字段及静态文本可访问性树断言错误保留为 calibration 日志，修正的是验收夹具，未添加产品 fallback。

没有修改 Node 协议、持久化 schema 或模型行为，不运行无关全量测试，不新增 UI 单测。原生历史是预置的真实 Pi 文件格式，不冒充这轮模型推理；所有模型请求被本地服务记录并拒绝，最终验收无模型请求。窗口操作通过独立副本中的原生事件/点击与渲染探针完成，生产源码没有验证钩子。未实际唤起 Finder/资源管理器，不声称物理输入或 Windows GUI 验收。此批源码没有重打 Mac ZIP。
