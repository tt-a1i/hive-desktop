# 远程接入的 Mac 原生界面补验

2026-11-09，基于b3e4b36。本轮为源码runtime及原生开发窗口验证；固定Hive原有远程业务与协议，未构建新ZIP。

## 实际环境与操作

`.artifacts/remote-native/`为独立数据/项目/Pi目录。自有HTTP/WebSocket回环网关只监听127.0.0.1；通过原始remote CLI完成测试账号登录。它没有连接生产网关、个人手机或用户账号，也没有模型请求。临时token只保存在该隔离数据及网关内存，不输出。

原生工具实际操作了：

- 设置→远程接入，读取已连接状态、当前回环网关和空设备列表。
- 1184×1104像素窄窗中滚动到配对入口，点击添加设备，复制配对码并粘贴到本地设置搜索；值与界面完整配对码相等，随后清空搜索。
- 回环手机对端使用原有X25519公钥/会话盐发送hello，实际daemon生成待确认设备及安全短码；界面出现对应设备、提示、短码及操作。没有点击确认或授予设备访问。
- 点击拒绝，原生卡片消失，原审计增加user_rejected，设备列表仍空。
- 仍有待确认请求时返回聊天，实际出现全局提醒；点击查看配对请求返回远程设置。
- 关闭再开启同一隔离网关，实际状态从已连接→已关闭→已连接；未修改其他数据目录。
- 复制状态命令再粘贴到本地设置搜索，确认引用实际包内Node、源码remote-cli及本轮独立state目录；没有执行这条粘贴命令。
- 最终构建切到英文，实际状态、配对码、设备、核对说明、安全短码及拒绝按钮均提供英文标签，设备原名称保留。英文拒绝成功，刷新完成后没有遗留“正在重新读取”提示。

三次原生窗口PID702、34035、84463均正常Cmd+Q并exit0。退出后回环网关确认daemon已断开；只停止本轮已核对PID/命令的网关进程。SQLite只读核验有3条user_rejected拒绝记录、0个配对设备，网关没有收到pair/confirm。具体脚本、日志、位置、receipt.json和probe-final.json保留在该目录。

## 实际发现与修复

修复前，连接状态、配对码、安全短码与设备核对说明仅视觉可见，辅助功能树只有操作按钮。现为状态/错误/操作提示标注Status，为配对码、设备名称、说明及安全短码标注Label；确认/拒绝按钮的可访问名称附带设备身份，确认按钮同时包含安全短码。中文与英文AX树实际读回完整值，视觉内容和协议字段未改变。

另发现操作成功后虽已刷新实际状态，界面仍永久保留“操作已提交，正在重新读取实际状态”。成功刷新后仅清除Submitted提示，错误提示保持；最终实际开关与拒绝流程确认旧提示不再残留。失败读取不清除提示，不伪称状态已更新。

最终源码通过`cargo build --locked --manifest-path apps/desktop/Cargo.toml`、`PATH="/opt/homebrew/opt/llvm/bin:$PATH" cargo check --locked --manifest-path apps/desktop/Cargo.toml --target x86_64-pc-windows-msvc`及`git diff --check`。仅原生展示/提示状态，无业务协议/schema/Node改动；不新增UI测试、不重复全量测试或后端远程suite。原有后台加密/SAS/终端测试证据按其范围保留。
