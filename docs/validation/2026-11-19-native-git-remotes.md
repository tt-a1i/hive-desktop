# 原生窗口的 Git 远端流程

macOS arm64 本地优化包 `9f5ec10` 使用原生窗口、独立 Hive 工作区及会话工作树。保留真实 Git 读写，用本地 bare 仓库作为推送目标。GitHub PR 使用受控 `gh` 进程，保留桌面、JSONL、原生进程、表单正文文件及结果检验路径。[功能任务 #43](https://github.com/tt-a1i/hive-desktop/issues/43)

## 推送和 PR

1. 选中会话工作树的本地远端并预览。预览显示原工作树路径、提交和目标分支。独立在该工作树增加一次提交后，旧确认被拒绝，本地 bare 仓库未新增引用。
2. 重新预览显示新提交。经窗口确认，Git 推送成功。独立核对 bare 仓库的分支 OID 和文件内容与正确的工作树提交一致。主项目 HEAD 和文件保留原值。
3. 切到受控 GitHub 远端。head 缺少当前提交时，预览仍展示完整标题与多行正文，创建按钮禁用。受控对端记录该提交后，窗口创建草稿 PR。观察到实际 `--draft` 参数与私有正文文件，随后读取同一个 PR 编号核对正文及 head。
4. 从窗口修改标题和正文，再预览并更新同一个 PR #17。受控对端核对两次写入、原编号以及包含中文和换行的原始正文。两个临时正文文件均已清理。此次流程没有写入 GitHub 或发布开发包。

首轮 PR 预览的测试程序位于上层仓库内，被产品的可执行程序信任检查排除，因而使用了系统 Git 做只读预览。后续把受控入口放在仓库外并复验，独立调用记录确认所有 PR 创建及更新均由受控进程处理。推送结果能通过辅助功能读取状态，PR 结果的详细状态文字仍未在辅助功能树中读出。当前 Windows 版本的原生远端操作待验。

## 语音退出范围与打包

按用户更新从开发分支移除听写控件、原生实现、系统权限声明和 Windows 专项。用真实 macOS 窗口填写普通聊天草稿，冷重开后文本和发送按钮状态均恢复。最终应用的 Info.plist 不含麦克风与语音识别用途声明，原生可执行文件不再链接对应的 Speech 与 AVFoundation 框架。

实际 macOS 窗口关闭收到后台退出确认，三次运行中观察到的桌面和后台进程均退出。标准脚本重新打包并签名，ZIP 解包验签，28,956 个文件、29 个链接和 2,709 个目录逐项一致。解包后 Node、PTY、Hive HTTP/SQLite 与关闭冒烟通过。Rust 测试 121 项通过、1 项辅助进程入口按设计忽略，Windows MSVC 交叉检查通过。没有开始模型回合、尝试登录或重新安装产品。

证据位于 `.artifacts/desktop-without-dictation-8f5f5N/`，包括 `native-receipt.json`、原生辅助功能树、Git 及受控进程记录、应用清单和 ZIP 校验摘要。
