# 任务编辑草稿退出后恢复

日期：2026-11-08。完整桌面目标仍在实施。

## 问题与可见变化

协作概览的任务编辑内容原先只在 `Collaboration.task_drafts` 内存中保留。用户编辑多段任务、切换项目后退出应用，再打开便失去尚未保存的文字，也失去处理冲突时已看到的远端版本。

现在任务草稿复用现有 `desktop-drafts` 存储：编辑后延迟保存，退出时立即保存，重新进入协作概览恢复对应项目的编辑器。即使用户把任务文档清空，空草稿也保留。草稿同时保存最初编辑基线和已确认的冲突版本；恢复不会把旧草稿直接写入团队文档。界面明确区分“本机草稿”和“保存任务”。不修复会继续造成正常退出后的编辑内容丢失。

## 实现边界

- 沿用 `DraftStore` 的路径校验、原子文件替换、写入成功后更新内存和退出失败阻止关闭；存储未能打开时也不能把任务草稿静默当作已保存。新增 `tasks:<workspaceId>` 草稿范围，不新增 Hive schema、任务账本或 HTTP 接口。
- `SavedTaskDraft` 保存精确 input、base 和可选 conflicting_content。不保存瞬态 saving 标志，也不在恢复时自动提交。
- 尚未打开的项目草稿保留为数据，打开该项目的协作页才创建原生编辑器；普通聊天草稿刷新不会清掉未打开项目的任务草稿。
- 保存任务继续调用既有 `workspace.saveTasks`，携带恢复前的基线，复用真实 HTTP / 文件比较更新逻辑。保存前先持久化本地草稿，失败时不请求更新团队文档。
- 任务保存成功后清理本地草稿；本地清理失败明确报告，并允许退出时重试。用户丢弃草稿时若磁盘删除失败，则保留编辑器和原改动，修复后可重试。移除工作区也清理对应活动/未打开的本地任务草稿。
- 旧聊天草稿格式继续读取，原有附件及失败消息关联不变。新增任务草稿明确校验 scope 与内容类型，文件名仍限制为安全 ID。

## 验证

Mac 原生 GPUI + 真实 Node/Hive HTTP/SQLite/任务文件，每个外观跨四次应用启动：

0. 预置损坏的本地草稿 JSON，实际启动读取失败。编辑任务后，保存不会发起远端写入；退出被阻止，编辑仍保留。用户显式丢弃后才允许退出。测试随后移除该损坏文件。

1. Alpha 编辑多段中文，确认延迟保存已写入磁盘；切换 Beta，把文档清空为尚未提交的空草稿；再回到 Alpha 后退出。两份本地草稿均保留。
2. 在应用关闭时由外部修改 Alpha 的真实 `.hive/tasks.md`；重开恢复 Alpha 原输入及原基线，Beta 空草稿仍保留。点击保存触发真实冲突，远端文件没有被覆盖；冲突版本也随退出持久保存。
3. 第三次启动恢复冲突及草稿，合并编辑后实际保存，确认团队文件内容和本地草稿清理。打开此前未进入的 Beta，空草稿完整恢复；将本地草稿文件暂时替换成目录制造删除错误，丢弃失败后编辑器仍保留，修复磁盘后再次丢弃成功，Beta 团队文件保持原内容。

浅色、深色、760px 宽窗口分别执行。夹具使用 GPUI 注入鼠标事件、原生 Textarea 输入和真实窗口渲染；不是物理鼠标键盘或 Windows GUI 验收。没有模型/厂商请求，没有操作用户项目或真实账号。

新增磁盘单元检查覆盖空编辑、冲突基线、重开和删除失败后缓存保留/重试。既有聊天/图片草稿检查只增加存储参数，原断言不变；没有删除现有测试。风险匹配的检查为 Rust 单元/生命周期、Hive host 实际 HTTP/SQLite/CAS、原生任务流程和 Windows 默认桌面特性 MSVC 编译；没有跑全量 Node suite，Node 业务没有改动。

本地证据保留在 `.artifacts/task-drafts/`：三份 `native-*-receipt.json`、各阶段日志、冲突及恢复截图、seed 和原生夹具脚本。临时数据位置由收据 data 给出，不作为产品目录约定。

实际检查：`cargo test --locked --manifest-path apps/desktop/Cargo.toml`（20 通过，1 个专用夹具忽略）；Windows MSVC 默认桌面特性 `cargo check`；`pnpm --filter @hive-desktop/runtime check:hive`。普通退出会同步保存；强制结束前尚未经过延迟保存的最后一段编辑不在本轮保证范围。

Mac 生产构建及冻结依赖部署生成 `.artifacts/hive-desktop-macos-arm64-tasks.zip`；解压后的包内 Node、真实 PTY、Hive HTTP/SQLite、退出烟测和原生窗口导航恢复通过。包未签名、公证，不视为正式安装发行。Windows 本轮只有编译检查，原生交互仍待验收。
