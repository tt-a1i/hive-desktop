# 协作页面自动更新

日期：2026-11-08。完整桌面目标继续实施。

## 真实问题

用户打开成员列表或协作概览后，成员被改名、派单新增、协作消息追加或任务文件被 Agent 修改，页面原先主要依赖手动刷新。已展开的消息分页若重新从第一页读取，还会丢掉已加载范围。

现在当前协作页面每 3 秒通过已有接口读取一次状态，保留派单筛选、页码、当前详情和滚动位置。自动读取的成员或协作错误明确提示旧数据未更新，不把失败当作停止或清空列表。任务编辑时不读取覆盖草稿。

不做会让用户在协作过程中持续手动刷新，或依据过时状态判断成员和派单进展。实现借鉴 Hive Web 已有的状态定期读取方式，没有引入新的事件总线或协作账本。

## 实现

- 复用 `team.members`、Hive 派单/消息及任务文件的既有 HTTP 接口。只读更新，不自动派单、汇报、关闭任务或启动模型。
- 仅在相应页面当前可见、后台连接正常时启动下一次读取。设置、角色配置和记忆页面不触发此轮询；成员编辑/新建/模型选择时不刷新成员表单。这里的可见指应用内页面，不包含 OS 最小化节流保证。
- 每类自动读取使用已有 generation 和独立进行中标志，避免同类自动请求叠加；手动切页、切换工作区、重连和编辑开始使旧结果失效。
- 任务文件未改变时不重建 Markdown；编辑及恢复草稿存在时不覆盖它。真实读取失败保留上次内容，后续成功清除错误。
- 派单列表自动更新当前 filter/offset，保留选择和旧列表直到成功返回。人工切换筛选和页码沿用原入口。
- 消息刷新沿用 Hive 2.2.1 每页 100 条的游标接口，仅重新读取已经展开的页数。更新已有消息的投递状态，同时追加该范围内的新消息；自动读取失败后的“重试”继续刷新全部已加载页，不沿用“加载更多”的追加游标；更多历史仍由“加载更多消息”显式展开。不会每轮无界读取全部历史，也不会把两页重置为一页。明细 ScrollHandle 保留。
- 成员列表读取失败使用本页错误提示，保留原成员和状态；不覆盖其他页面的全局错误。

## 原生验证

真实 GPUI、Node、Hive HTTP/SQLite/任务文件。原生夹具专用 sidecar 增加一个仅供测试调用的认证变更入口，使用实际 runtime 铸发的主控 token 调现有 Hive HTTP 路由；不替换 fetch、存储或业务结果，该入口不进入生产源码或包。主控投递队列在夹具中暂停，成员保持停止。本轮没有厂商推理，也没有本地模型请求。

- 通过真实 HTTP 改名成员，等待定期读取使界面自动更新，没有点击刷新。
- 外部写任务文件后自动更新。将任务文件临时替换为目录触发真实读取错误，旧文字保留；恢复文件后错误自动清除。
- 编辑任务草稿期间外部更新文件，等过一个刷新周期，编辑内容保持不变；丢弃后读取最新文档。
- 通过真实认证 HTTP 创建 26 张排队派单及 110 条说明消息。选择 queued、offset 20；新增第 27 张后页面自动更新，filter 和 offset 均保留。
- 选中目标详情，第一页显示 100 条，经过刷新周期仍只有一页；滚动到底部并点击“加载更多消息”，显示 110 条。
- 在已加载 110 条消息后，由夹具在真实 HTTP 读取完成后注入一次合成传输异常。旧消息保留，点击“重试读取消息”重新读取已展开的两页，验证过程中没有重复追加第二页。显式重试检查期间暂停定时更新，避免下一轮自动读取掩盖按钮失效；重试成功后恢复定时更新，再验证追加和取消。该异常是客户端错误路径的故障注入，不是服务端故障实测。
- 新增说明并取消派单后，详情状态、原消息投递状态及新说明自动出现，111 条 ID 不重复，已展开范围和阅读滚动位置保留。
- 切换到 Beta 后，Alpha 的派单和任务不出现在 Beta 视图。

夹具使用注入鼠标事件、原生 ScrollHandle 和真实窗口渲染，不等同物理鼠标或 Windows GUI 验收。取消派单验证的是账本、消息和界面同步；停止中的 Worker 没有活动 run，原生取消提示投递按 Hive 现有逻辑返回 forward_error，日志保留，未把它当作运行中工具已取消的证明。

初次夹具向成员发送 progress 被真实协议拒绝，已改为主控到成员的 note，没有改协议迎合测试。分页走查明确先滚动到底部再点击加载更多，避免向视口外按钮注入无效点击。

证据保留在 `.artifacts/live-collaboration/`：各外观原生收据、日志、成员/派单/错误/详情截图、seed 及夹具脚本。临时数据及源码目录由收据定位，属于本机验证材料，不是生产路径约定。

## 范围

这是定期读取而非服务端推送，不保证瞬时更新；多页刷新费用随已加载页数增加。长历史进一步的资源度量、Windows 原生交互和真实模型驱动的持续协作还有独立验证边界。本轮没有改 Node/Hive 核心协议、schema 或依赖，没有新增/删除表面 UI 单元测试。

本轮浅色、深色、760px 原生场景分别通过，三份收据均为零模型请求，并包含自动读取失败后重试不重复追加的断言。`cargo test --locked --manifest-path apps/desktop/Cargo.toml`：20 通过、1 个专用夹具忽略；`pnpm --filter @hive-desktop/runtime check:team` 通过；Windows 默认桌面特性 MSVC `cargo check` 通过。没有跑全量 Node suite：改动集中在原生只读更新和视图状态，采用真实团队协议回归与原生窗口走查。

Mac 生产构建和冻结依赖部署生成 `.artifacts/hive-desktop-macos-arm64-live.zip`。解压后的 Node、真实 PTY、Hive HTTP/SQLite/退出烟测及原生窗口导航恢复通过；包内 main.js 与生产 dist 一致，不包含夹具认证入口或故障注入，二进制与生产构建哈希一致。包未签名、公证，Windows 本轮仅编译检查。早于重试修复的包保留为 `live-pre-retry.zip` 并标记被替代，不作为最新交付。
