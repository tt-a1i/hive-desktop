# 按 Codex Agent 配置读取账号额度

在「设置 → Agent 配置」选中已启用的 Codex 配置，即可手动读取该配置的额度。面板标出当前保存的版本，通过同一后端使用该版本的可执行文件、参数与配置目录。仍可在「外部程序」检查默认 Codex。两个入口各自保留最近一次检查状态，关闭或重启应用后需要重新读取。

读取请求绑定后台连接、配置 ID、版本与当时的配置状态。切换配置时旧结果不会显示在新的配置下。每个入口同时只运行一次探针。原生账号探针只请求允许公开给面板的字段，额度窗口、普通使用资格、时长及重置时间仍有独立的未知状态。

## macOS 原生验收

在隔离目录运行本地签名的 arm64 应用，通过 Agent 配置页面完成以下操作。

- 对 Alpha 发起迟到回包测试，在返回前切到 Beta。后台收到 Alpha 的窗口，Beta 未显示它。Beta 读取使用自己的保存参数及独立 `CODEX_HOME`，表单中的未保存参数保留在草稿。界面显示受控次要窗口的真实数值、普通使用受限，缺失时长和重置时间明确显示未知。
- 对官方 CLI 0.169.0 发起一次实际只读额度检查。现有 Codex 账号返回一个主要窗口，界面在对应配置下显示百分比、时长和重置时间。原生请求为 `account/read {refreshToken:false}` 与 `account/rateLimits/read {excludeResetCreditDetails:true}`。没有登录或模型调用，验证收据只记录状态与窗口数量。
- 正常退出后冷启动。Beta 恢复保存的参数和版本，未沿用额度或启动新探针。测试实际启动的三条探针均正常退出，两次桌面退出均有后台确认。

Codex 额度协议专项、117 项 Rust 测试、macOS 包内 Node、原生 PTY、Hive HTTP/SQLite 与关闭冒烟均通过。Windows x86_64 MSVC 交叉检查通过，原生窗口仍待验证。开发包仅在本地使用，未发布。
