# 窗口内恢复后台

2026-11-08。

后台连接失败时，窗口提供“重新启动后台”。操作前保存聊天草稿，等待既有进程监督器确认旧后台及其受管进程范围退出，再启动新的后台。清理失败时保留原所有者与错误反馈，用户可以重试。重试进行时入口禁用。

恢复后重新读取工作区、会话与配置。聊天输入、任务编辑、配置路径及当前面板保留在原生客户端中。每轮连接带独立代次，旧的会话、成员、设置、任务和交互请求结果不能更新新连接的界面。发送结果尚未确认的输入保留在复制区，供用户核对。已有待处理消息沿用原来的显式继续语义。

## 实际检查

- macOS 原生窗口使用独立临时数据目录。强制结束该窗口的 Node 子进程后，恢复入口出现。点击后原成员会话、已保存的名称、工具过程和未发送草稿恢复。
- 第二次强制结束后台发生在任务编辑页。恢复后仍在原编辑页，未保存任务保持原文。随后打开设置，先前未保存的 Codex 路径也保持原文。
- 两次恢复均保持同一个原生窗口进程。检查确认先前两个 HTTP 端口关闭，当前原生窗口只有一个 Node 子进程。
- 初始运行路径缺失时，原生窗口显示恢复入口。补回测试入口文件并点击重试，原工作区、会话名称及磁盘中的聊天草稿恢复。
- 锁屏后用带断言的原生程序检查“已提交、响应中断”。真实后台完成配置写入，测试垫层暂扣该成功响应，再 SIGKILL 受管后台。恢复后确认旧进程所有者已经过清理屏障，旧端口不可连接，新端口不同；原路径输入与实际配置快照一致，界面没有把已保存内容标成未保存。垫层没有生成业务响应。
- Rust 定向检查 14 项通过、1 项既有 fixture 入口忽略；包含真实进程监督、退出与管道关闭检查。真实 Hive HTTP/SQLite、Pi SDK 与 team CLI 的无推理协作回归通过。
- Windows 原生脚本增加了强制结束当前窗口受管 Node、点击恢复、核对替代进程数量、恢复汇报入口和草稿的检查。GitHub 账户计费限制下尚未实跑。

## 边界

这是后台重新启动及已有会话的恢复。中断中的厂商工具执行需要用户核对工作区和会话状态。进程清理继续遵守既有 macOS 进程组 / Windows Job 范围；主动离开 macOS 受管进程组的进程仍在该边界之外。

本轮没有发送模型请求。活跃模型回合、活跃外部 CLI 工具、macOS 脱离进程组的工具，以及 Windows 本次恢复入口仍待分别验证。
