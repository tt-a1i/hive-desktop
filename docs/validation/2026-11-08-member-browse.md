# 团队成员搜索与协作状态筛选

## 真实问题

同一项目有较多成员时，原生页面只有完整列表，定位某个成员、某类角色或后端需要反复滚动；进入成员会话再返回也缺少明确的定位条件。现在可在成员页按名称、角色（中文或原始角色值）、Agent 后端搜索，组合全部/工作中/待命/已停止筛选；显示各状态人数和当前匹配人数，并提供清除筛选与无结果提示。

不增加新的协作状态、调度能力或数据存储。搜索与筛选仅作用于当前工作区已读取的成员，状态人数来自当前工作区完整成员集。搜索条件在当前应用进程中保留，切换项目也保留条件；当前项目无匹配时明确提示，清除后显示该项目成员，不引入其他项目的数据。

## 协作语义

`@tt-a1i/hive` 2.2.1 的 `workspace-store-support.js` 按 pendingTaskCount 推导工作中/待命。工作中表示有未结派单，不等于模型正在回复；回复结束不代替 `team report` 或 `team cancel`。界面明确说明该语义。停止仍是原来的停止成员运行操作，搜索不改变成员、运行或派单。

## 原生验证

夹具使用隔离目录、真实 Hive HTTP/SQLite、32 个真实成员（Alpha 30，Beta 2），其中一位 Pi 成员创建原生会话。验证渲染后的可访问节点、实际鼠标事件及原生截图，而不是只核对内存筛选函数。

覆盖名称搜索、Codex 后端搜索、中文角色搜索、无结果与清除；从筛选结果进入实际成员会话并返回，保留查询；真实启动后显示待命，真实派单后显示工作中、取消后恢复待命；外部 HTTP 改名通过现有自动读取反映到匹配结果；真实停止后显示已停止；切换 Beta 并清除条件时只显示 Beta 的成员。

回执、截图和夹具源码在 `.artifacts/member-browse/`。原生事件注入不代表物理键鼠或 Windows GUI 验收。模型配置只使用 gpt-6.1-terra；启动恢复过程中可能产生发往本地端点的请求，端点显式拒绝执行，不构成厂商推理成功。统计只展示真实协作状态。

验证过程中曾尝试用“模型生成中”构造 working，原生检查失败；追查安装版 Hive 的权威状态规则后，改用真实派单与取消验证，生产协议保持不变。首个 seed 使用了不存在的 stop 路由，已改为读取真实 run 并调用现有 runtime stop，未为夹具修改产品路由。

本轮为原生 UI 调整：完整桌面编译、Windows MSVC 默认功能编译、macOS 原生常规/窄窗与深色走查为验证方式；不新增 UI 单测，不重复无关运行时全量套件。Windows 实际 GUI、物理输入与完整产品体验继续验收。

实际静态验证命令：`cargo check --locked --manifest-path apps/desktop/Cargo.toml`、`PATH=/opt/homebrew/opt/llvm/bin:$PATH cargo check --locked --manifest-path apps/desktop/Cargo.toml --target x86_64-pc-windows-msvc`；最终恢复入口使用 `cargo build --locked --manifest-path apps/desktop/Cargo.toml`。本批未重新生成分发 ZIP；此前模型入口开发包不包含此次成员筛选，不能作为本批界面验收包。
