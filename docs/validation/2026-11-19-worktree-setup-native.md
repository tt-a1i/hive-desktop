# 工作树初始化的 macOS 原生验收

## 源码对照

Apache Maka 的 `rust-preview` 固定参考 `158d79f514dbd5bb6be89b668a5cfb81e5b3a2a2`。它的 Unix PTY 分别处理退出进程组、等待前台任务和排空输出。架构文档也要求保留未知执行结果，避免把缺少回执当作可自动重放的证据。[PTY 进程退出](https://github.com/apache/maka/blob/158d79f514dbd5bb6be89b668a5cfb81e5b3a2a2/platform/process/src/pty/unix.rs) · [事件和恢复](https://github.com/apache/maka/blob/158d79f514dbd5bb6be89b668a5cfb81e5b3a2a2/ARCHITECTURE.md)

Hive 保留现有脚本进程所有权、输出日志和初始化状态记录。初始化启动完成、启动失败、原生进程退出时，后台发出轻量通知，只携带项目和会话 ID。当前窗口读取后台确认的状态，忽略另一会话或旧请求的响应。打开会话时仍在运行的脚本会补读一次，覆盖脚本在打开响应到达前就退出的情况。窗口无需增加轮询定时器或保存脚本正文。初始化完成后仍由用户显式打开会话。

## 实际操作与结果

使用隔离数据目录、真实 Git 仓库、包内 Node 和本地临时签名的 macOS arm64 应用。窗口通过项目菜单创建独立工作树，脚本经现有 PTY 执行，使用文件控制测试脚本的退出。

| 操作 | 观察结果 |
| --- | --- |
| 创建工作树并等待脚本 | Git 确认会话使用独立工作树，脚本在该目录写入标记。运行期间发送按钮不可用，界面提供停止并跳过操作。 |
| 让脚本以 23 退出 | 无需点击刷新，窗口出现“重试原初始化脚本”和“跳过初始化”。项目脚本设置显示失败和退出码，原生 PTY 日志包含失败标记。辅助功能树可读取失败状态及脚本名称。 |
| 修改并保存脚本后重试 | 原会话重试使用同一工作树和冻结的脚本版本，生成新的运行请求，退出码为 0。窗口自动显示“打开会话”。打开后输入草稿，发送按钮可用。 |
| 为后续工作树使用新版本 | 新版本在自己的工作树写入不同标记并以 31 退出。显式点“跳过初始化”后可以打开该会话。 |
| 在创建对话框中跳过 | 新工作树可直接打开，后台记录为 `disabled`，没有新脚本运行记录。 |
| 正常退出并冷启动 | 重新打开时恢复已跳过的会话。切回成功工作树，原草稿和执行目录一致。两次退出均收到后台确认，应用退出码为 0，验收进程已清理。 |

原仓库的受 Git 跟踪文件未变化，项目根目录没有测试脚本的输出标记。四个工作树产生四次脚本执行，其中两次属于同一个工作树。此次验证未发送模型提示。

## 检查

- `pnpm check` 和 `pnpm --filter @hive-desktop/runtime check:worktree-setup` 通过。JSONL 回归核对初次运行和重试的通知只传项目与会话 ID。
- Rust 测试 116 项通过，另有一项子进程测试入口按设计忽略。Windows x86_64 MSVC 交叉检查通过，尚缺 Windows 原生工作流证据。
- 证据保存在本地 `.artifacts/worktree-native-VGlE3e/`，包含包、两次应用退出日志、项目与脚本运行记录、复核结果 `receipt.json`。包内 Rust 可执行文件和后台 JavaScript 均取自本轮构建，更新后通过 `codesign --verify --deep --strict`。

## 后台强制退出时回收脚本

GPT-6.2 Sol 在真实 macOS PTY 中复现了两种残留。Node 被 `SIGKILL` 后，忽略挂断信号的初始化脚本及其 `sleep` 子进程继续运行。手动脚本的 shell 如果正常响应挂断信号，其 `nohup` 子进程也可能继续运行。旧包的原生窗口通过“重试原初始化脚本”再次复现了第一种情况。

macOS 已保存脚本通过现有 Rust 进程监督入口启动。监督进程验证自己是隔离 PTY 进程组的组长、直接归属于本次 Node，收到 Node 退出通知后结束自己的进程组。它仅在脚本执行期间运行，无需启动桌面界面。脚本仍使用原执行目录、PTY 输出、常规退出码和原生退出信号。验证覆盖仍在同一进程组中运行的脚本及子进程。

从新版 ZIP 解包后，在三个独立工作树的原生窗口中重试已保存的初始化脚本。点“停止并跳过初始化”和正常退出窗口均清理了监督进程、脚本及子进程，两次运行都记录取消和信号 15。第三次强杀 Node 后，系统进程表中的三个进程全部消失。冷重开显示中断，重试和跳过不可用，工作树里的执行标记只写入一次，原仓库的受跟踪文件没有改动。三次运行中的监督进程 RSS 约 11.6 MiB，进程退出后回收。

另复现了冷启动无法读取已丢失的脚本日志，导致整个 Node 后台启动失败。现在该次执行保留为中断，运行记录标明日志缺失，打开对应日志会得到明确错误。项目列表和其他运行仍可读取。强制退出后保留一次执行记录，不自动重放。后台重启后继续按已记录的执行结果决定是否允许重试或跳过。

项目脚本和初始化专项检查通过，包括工作树退出、取消后的进程回收、原生退出信号、日志截断、冷启动不重放和日志缺失。127 项 Rust 测试通过，另有一项子进程测试入口按设计忽略。Windows x86_64 MSVC 交叉检查通过，当前 Windows 原生脚本生命周期仍待验收。包内 Node、PTY、Hive HTTP/SQLite 和退出冒烟通过。本轮未调用模型，未发布。

源码版本为 `4a4cc18`。macOS ZIP 解包文件与签名均已核对，归档含 28,956 个文件、29 个链接和 2,710 个目录。ZIP SHA-256 为 `b9fec0e81b689e383beccdb355a1dcd9e46e7c8a0740c7c6ebe7f735a41da607`。本地证据位于 `.artifacts/script-owner-PPLizL/`。原生窗口对照见 `baseline-oJUE7j/receipt.json` 和 `candidate-Hmb8D5/receipt.json`，包内工作树、手动 `nohup` 脚本和丢失日志的 JSONL 对照见 `sol-isolated/`。
