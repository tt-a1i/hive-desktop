# Codex 会话原地回退与代码检查点

[#50](https://github.com/tt-a1i/hive-desktop/issues/50) 的原地回退入口位于 Codex 用户消息旁。预览显示要移除的回合数，确认后先备份完整对话与当前代码。独立工作树可以恢复到选定的检查点，共享项目目录只回退对话。原会话 ID 保留，备份会话可以单独打开。任务、派发、消息和报告回执继续由 Hive 的原有记录管理。

回退之前核对原生会话、Git 工作树及 Hive 协作状态。只有通过独立校验的空闲来源会话可以自动关闭。其余活动 Agent、未完成交付及运行中的终端会阻止回退。应用在原生请求前持久化操作状态。请求结果不明确时原会话进入只读状态，手动核验通过后可接着恢复代码并打开备份。

真实 Codex CLI 0.169.0 会在原地回退时更换 rollout 文件，但会话 ID 和保留回合不变。验收中第一次回退因旧路径检查停在待核验状态。修复后通过生产 JSONL 入口冷启动恢复该次操作，原生回退只发送了一次。原会话恢复了检查点的磁盘文件和暂存区，备份中的两者分别保留回退前内容。之后使用 GPT-6.1 Terra 在相同原生会话 ID 上续聊，准确取回前一个回合的随机标记。工作目录和数据目录均为本地验收专用，真实调用仅用了固定的 Codex 配置。

## 检查与证据

- 实际 Git 检查覆盖 HEAD、暂存区、工作树、符号链接、文件与目录切换、忽略文件、外部改动、Git 锁及中断后的继续恢复。
- 生产 JSONL 与受控原生对端覆盖提交前确认、备份顺序、回退前后两种回包丢失、原生路径变化、冷启动核验、原协作交付回执和请求 ID 重放。另关闭桌面输出管道并保持输入打开，验证后台正常回收并以状态 0 退出。
- macOS 原生窗口完成预览、确认和打开备份的实际操作。冷启动后核对原会话长度和备份中的历史，窗口正常关闭，已观察的子进程全部退出。确认和重开分别记录在 `desktop-confirmation.log` 和 `desktop-reopen.log`，退出收据为 `gui-receipt.json`。
- Rust 单测 115 通过、1 项辅助进程入口按设计忽略。Windows MSVC 交叉检查通过。Windows 原生回退窗口和安装包运行仍需单独验收。
- 本地 macOS 开发包带独立应用身份，并通过严格代码签名验证。包内 Node 和后台通过 Git 恢复、旧分叉协议、回退和管道断开检查。产物及日志位于 `.artifacts/native-rewind-mac-IBjP4y/`，真实 Codex 收据为 `evidence/receipt.json`。
