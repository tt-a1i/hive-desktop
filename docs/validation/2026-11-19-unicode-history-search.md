# Unicode 历史搜索摘要

项目侧栏和全局搜索现在按同一套 Unicode 规则匹配会话名称与正文。摘要从匹配位置附近截取，避免把规范化后的位置用到未经规范化的正文。大小写转换改变长度时，优先显示仍可定位命中词的规范化原文，必要时显示用于匹配的文字。结果保留原消息 ID，侧栏可见摘要、悬停提示和辅助功能标签都提供命中内容。

会话列表每个会话只生成一条摘要，完整性检查仍覆盖整份历史。摘要按字符边界截取固定大小，不为长正文构建整条字符数组。

## macOS 原生验收

本地签名的 arm64 开发包使用同一隔离项目和一份含 91 条已保存消息的历史。早期命中消息在关键词前有 400 个组合字符。

- `81250fd` 对照包找到了会话，实际侧栏摘要只显示关键词之前的一段文字。
- 修复版用组合形式或单字符形式输入带重音的查询。项目侧栏和全局窗口都显示了命中词，辅助功能可读。点击两种结果均跳到早期原消息，视口显示其邻近消息。
- 冷启动按既有行为回到该会话末尾，重新搜索仍能从全局结果跳到同一条原消息。核对 91 条消息的 ID 与正文，全部与写入的夹具一致。三个窗口正常退出并确认后台关闭，进程全部回收。

## 内存测量和回归

用同一份包内 Node 22.23.3 运行两版后台的摘要代码，每版七次，交错在新进程内查找一条 150 万字符消息末尾的命中词。进程峰值 RSS 中位数从 77.9 MiB 降到 64.9 MiB。该数据衡量 Node 搜索路径。

五组源码搜索回归和相应的包内检查通过。首次运行包内元数据回归时，独立环境缺少检查所依赖的 Pi 模型名称。检查现使用临时目录的本地模型定义，验证空闲 Worker 的原生身份和重命名，不依赖用户的模型配置。Rust 118 项通过，另有一个子进程入口按设计忽略。macOS 签名与包内 Node、真实 PTY、Hive HTTP/SQLite 和退出冒烟通过。Windows x86_64 MSVC 交叉检查通过，尚未在 Windows 原生窗口复验。本轮没有调用实际模型或发布。

隔离包、两版窗口日志、原生回执、包内回归回执和逐次测量位于 `.artifacts/unicode-history-search-rmzzZ6/`。

## 取消已经不用的历史搜索

优化包 `5ed4a2e` 让项目侧栏、全局搜索和归档设置拥有各自的搜索请求。替换查询、关闭对应界面或退出时会取消仍在运行的请求。后台用请求编号定位旧任务，关闭可取消的本地读取并停止继续扫描会话。当前查询仍使用完整历史、原消息 ID、项目及归档范围、分页和不完整历史提示。已发给 Claude 离线 SDK 的单次读取要等 SDK 返回，其结果随后丢弃。

- 通过生产 JSONL 对照上一个开发包与新包。探针只拉长普通文件各次实际读取的间隔，让取消在文件已打开时发生。旧版完成了 7,047,659 字节的读取。新版在首个 65,536 字节块后关闭描述符并返回取消状态。独立归档查询完整读完，新查询仍定位到第 3,199 条原消息。关闭应用时，仍在打开的搜索也被取消。
- 原生 macOS 窗口验证侧栏换词和关闭归档设置。两次旧搜索都在读取 524,288 字节后关闭，各自源文件约 7 MB。当前侧栏结果打开了原会话，辅助功能树读到原消息正文。关闭窗口后桌面和后台均退出。全局对话框的原生关闭操作未能从此次输入夹具复现，源码和协议验证保留。
- 实际读取取消的回归、完整正文搜索专项、122 项 Rust 测试及 Windows x86_64 MSVC 交叉检查通过。Rust 另有 1 项辅助入口按设计忽略。macOS ZIP 解包验签、内容比对、实际包内 JSONL 回归和 Node／PTY／Hive HTTP、SQLite 与退出冒烟均通过。Windows 原生窗口仍待验。本轮没有模型调用，没有发布，也没有替换本机安装。

证据位于 `.artifacts/history-search-cancel-q9WBHu/`，包括 `receipt.json`、对照与新包的流读取日志、macOS 辅助功能树和包校验摘要。
