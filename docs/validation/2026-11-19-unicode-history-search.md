# Unicode 历史搜索摘要

项目侧栏和全局搜索现在按同一套 Unicode 规则匹配会话名称与正文。摘要从匹配位置附近截取，避免把规范化后的位置用到未经规范化的正文。大小写转换改变长度时，优先显示仍可定位命中词的规范化原文，必要时显示用于匹配的文字。结果保留原消息 ID，侧栏可见摘要、悬停提示和辅助功能标签都提供命中内容。

会话列表每个会话只生成一条摘要，完整性检查仍覆盖整份历史。摘要按字符边界截取固定大小，不为长正文构建整条字符数组。

## Codex 冷历史索引与全局搜索断线

GPT-6.2 Sol 用独立的 Hive HTTP 和 SQLite 工作区复现了搜索与冷打开之间的差异。可选索引损坏或有重复条目时，旧版漏掉可读会话。索引含有可见记录里不存在的 ID 时，旧版也会返回无法跳到原文的结果。分叉继承和本地记录对同一消息有不同投递 ID 时，搜索返回继承 ID，冷打开却显示本地 ID。

`794e9f4` 让 Codex 搜索和冷打开从同一组可见记录读取正文。可选索引缺失、损坏、重复或与可见记录的身份不一致时，两处均提示历史可能不完整。搜索、冷打开和实时会话以同一规则优先匹配继承记录，再匹配本地记录，并兼容旧版按回合保存的投递收据。Rust 全局搜索窗口只在请求期间持有后台的引用。后台断开时，窗口取消读取，释放结果及滚动状态，并禁用旧结果导航。

用前一版和新版 ZIP 各自解包的 Node 与后台入口，分别创建两个独立 Hive 项目。对两包发送同样的生产 JSONL 请求。旧包的全局搜索只命中健康会话，项目筛选无命中，并返回了一个只存在于索引中的结果。新包的全局搜索命中四个可打开会话，项目内命中三个并逐一给出警告。另一个项目只命中健康会话。分叉消息用同一个继承投递 ID 搜索和打开。对照中的历史文件及收据逐字节未变，两个后台均收到退出确认并以状态 0 结束，无 Agent 事件和模型请求。

源码通过四组历史搜索、两组会话身份、十一组 Codex 检查，另通过分叉来源和桌面会话回归。Rust 测试 131 项通过，1 项辅助入口忽略。优化 macOS arm64 ZIP 经文件清单比对和解包严格验签，解包后通过五项相关后台回归及 Node、实际 PTY、Hive HTTP/SQLite、退出冒烟。Windows x86_64 MSVC 交叉检查通过。Mac 锁屏期间无法操作本轮原生窗口，断线清理仍待窗口复验。未发布或替换本机安装。
