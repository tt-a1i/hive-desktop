# 会话查找覆盖补丁与错误详情

此前查找匹配正文、思考、工具名称和调用参数，但新增工具补丁以及独立保存的回复错误详情不在匹配范围内。用户能打开这些内容，却无法通过会话查找定位。

现在共用匹配函数包含实际保存的 patch 和回复错误。补丁命中展开并定位对应工具，“查看改动 · 匹配”及辅助技术标签指出阅读入口；不把磁盘内容混入历史查找，也不自动打开弹窗抢走查找焦点。错误命中展开详情并更新虚拟列表高度。当前错误平时由输入区去重显示，选中它的查找结果时允许显示对应历史行，关闭或切换结果后恢复原去重规则，不改变待处理投递或重试语义。

补丁到达时按工具调用 ID 刷新当前查找；第一条新匹配或当前匹配失效后定位新选择，已有有效选择不被流式事件反复滚动。沿用逐条更新，不在每个流式事件全量重扫历史。

## 验证

使用真实 Pi Edit 工具生成包含中文上下文的补丁，保存到真实 Pi 会话，再通过 Hive 后台加载到 GPUI；查询只出现在补丁上下文、没有出现在调用参数/工具输出中的“第一行”，验证两个工具结果及键盘切换。错误来自明确预置的原生 assistant stopReason/errorMessage 记录，不是本轮厂商错误请求；初次夹具误用了 SessionManager entry ID，后按实际桌面消息身份定位，并保留失败日志。

常规浅色、760px 浅色及 760px 深色原生窗口检查：Cmd-F、实际原生文本输入事件、Enter/Shift-Enter、补丁入口匹配状态、错误详情展开与当前错误去重、Escape、原输入焦点和精确中文草稿保留。生产 ToolStart/ToolEnd 入口的合成事件另验证新 patch 由零匹配变为一条、自动展开/定位，以及后续记录更新移除匹配；不冒充实际厂商流式执行。没有模型请求，没有操作用户系统剪贴板。

`cargo test --locked --manifest-path apps/desktop/Cargo.toml`：23 通过、1 忽略；完整 Windows MSVC 默认功能类型检查通过。没有新增 UI 单测，没有修改 Node/Hive 协议、持久化格式、模型权限或队列，不重复 Node 全量 suite。原生夹具及收据位于 `.artifacts/find-details/`；结束后重新构建生产入口。

## 边界

查找仍限当前已加载会话内容，不是磁盘全文或完整仓库搜索；工具补丁命中以消息为单位，打开 Diff 后使用已有阅读/改动导航，没有冒充补丁内逐字符查找。Windows 原生窗口、物理输入法/键盘和真实账号推理仍需验证。本批未更新 ZIP，已有 file-preview 包对应 `480b7c7`，不包含后续 Diff 与本次修复。完整产品目标继续开放。
