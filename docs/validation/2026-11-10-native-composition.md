# 原生组合输入、取消与撤销补验

源码 `b8feb47`，Mac 自有状态副本 `.artifacts/input-click-b8feb47/`。本轮没有生产/测试代码或开发包变化；范围是前轮首次解锁后异常清空的继续调查，并非完整输入法验收。

## 已观察的真实行为

- 从前轮状态复制两条空 Codex 会话、两份精确草稿及空的自有 Pi 配置；原状态继续保留。两会话都选择 Terra，应用使用保存的原始 Codex CLI 路径，没有发送消息或调用模型。
- 点击已有中文多行正文，单个原生按键进入带下划线的组合输入；组合期间某次 `typeText` 没有得到目标文字。此结果未记为输入成功，也不能直接归因于产品丢字或剪贴板实现。
- 取消未替换选区的组合输入后，完整正文仍在。用真实 Cmd+A / Cmd+C / Right / Cmd+V 得到两份完整中文、emoji、多行正文连续拼接，见 `native-copy-paste.ax.txt`。
- 选择全文后，以原生 n/i 按键产生带下划线的 `ni`，按 Return 后仍留在编辑器，未触发发送；再次实际复制粘贴得到 `nini`，确认这次提交到了正文。见 `ime-preedit.ax.txt`、`ime-enter.ax.txt`。最终后台零新消息/投递/运行，不能只据 UI 未显示忙碌推断没有发送。
- 可重复观察到“选择全文 → 组合输入 ni → Escape”后正文为空；对另一条精确基线 `UNDO_KEEP · 中文原文 🐝` 重放相同条件，Cmd+Z 完整恢复该原文，见 `ime-cancel.ax.txt` / PNG、`ime-undo.ax.txt`。未把这种可撤销的选区替换直接定性为不可恢复数据丢失。

当前 gpui-base 0.9.0 的 `replace_and_mark_text_in_range` 用首个组合事件的选区替换正文，后续以空 marked text 取消时清除组合范围，整个替换归为一个撤销事务。源码契约与所观察的撤销恢复相符。本轮没有新增 Hive 专属取消兜底、计时器、全局光标状态或 vendored gpui-base 补丁。

## 对照限制

在系统 TextEdit 新建自有对照文稿；首次按键产生 `Ni`/英文大小写建议，未建立与 Hive 相同的组合条件。尝试现有输入源快捷键，但未取得可靠的输入源身份/同条件证据；系统菜单代理访问超时，几次窗口捕捉发生瞬时错误，后续继续检查了原窗口。导航中也曾遇到文字接口未正确填入路径，改用实际可见的本地文件选中/打开流程，没有把这些尝试算作 Hive 故障或成功对照。

自有对照文稿保存为 `.artifacts/input-click-b8feb47/native-reference.rtf`，最终正常保存、关闭到打开面板。没有读取其他用户文稿或修改输入源配置。现有输入源快捷键的尝试只用于本次比较；回到 Hive 后再次观察到最初的组合/取消/撤销行为，不宣称已识别或完整校准全部输入源。

因此，首轮“点击后 typeText 导致空正文”的原始根因仍未确定；本轮只复现了有明确选区替换条件的同类可见结果。系统编辑器取消语义对齐、所有输入源/候选选择、组合态切页/退出、Windows 与辅助技术仍待验证，不据此修改公共编辑语义。

## 保存与独立核对

两个 Hive 原生进程均 Cmd+Q exit 0。结束前显式恢复自有副本的原中文草稿；独立 SQLite/文件检查断言副本与原状态的两份草稿都与 `baseline-drafts.json` 精确相等。两条记录仍无原生 transcript；messages、dispatches、dispatch_messages、agent_runs、workflow_runs 均为零，见 `receipt.json`。没有新增厂商推理、认证或全局模型修改。

本轮没有生产改动，未新增/删除测试、未重复构建或运行全量 suite。原生证据不扩展到其他平台或开发包；完整目标保持进行中。
