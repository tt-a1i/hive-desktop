# 桌面更新的取消、清理和重试

本文末尾记录的旧身份格式与整包签名冲突已在[后续 macOS 整包签名更新](2026-11-19-macos-signed-update.md)中修复并用本地临时签名验证。

普通退出、安装前草稿保存失败、安装准备完成时检测到新任务这几条路径均会释放尚未启动的安装程序和恢复入口。可重用的已校验归档保留。后台只向收到确认的安装交接保留该次准备结果。桌面收到同一安装的确认并核对后台进程范围已退出后，才启动独立安装程序。

## macOS 原生验证

在隔离的 `0.1.0` 开发包中，通过设置页检查并下载回环渠道签名的 `0.1.1` 归档。文件共 163,032,775 字节，由 Ed25519 签名清单提供 SHA-256。沿用此前验证过的 `0.1.1` 更新归档，这次重建了负责准备和启动安装的旧版桌面及其包内后台。

1. 原生输入框保留新编辑的草稿，临时用隔离数据目录下的测试文件阻止草稿写入。安装准备成功后，窗口提示草稿保存失败。原应用二进制的 SHA-256、持久化草稿和新编辑内容均核对通过。
2. 生产 JSONL 回执确认安装准备及取消。安装目录和恢复入口消失，未出现安装结果，旧程序继续运行。重新计算缓存归档的大小和 SHA-256，结果与签名清单一致。
3. 恢复草稿目录，在设置中重新确认安装。运行期间只下载一次。包内后台确认安装交接，旧程序和后台退出。安装收据记录 `0.1.1` 已安装。新版真实窗口重新打开原会话并显示新编辑的草稿，设置页显示安装成功。关闭窗口后核对两版桌面、后台和安装进程均已退出。

真实包证据位于 `.artifacts/update-installer-ownership-mac-Vks4Xa/` 的 `receipt.json`、`discard-receipt.json`、`desktop.log` 及安装收据。该流程未调用模型，未替换已安装实例或公开发布。

## 回归与平台边界

更新专项中的真实子进程和文件系统回归在旧后台复现普通退出后遗留目录与恢复入口。修复后通过取消、过期标识、替换准备结果、普通退出、成功交接及保留归档校验。独立测试也通过正常替换、新版启动失败回退、安装进程中断后的恢复。类型检查通过，Rust 115 项通过、1 项按设计忽略，Windows MSVC 交叉编译通过。Windows 的最新原生替换仍需运行证据。

当前开发包由更新渠道签名清单保护归档，macOS 二进制为链接器临时签名。本地另对整个隔离 `.app` 作临时签名，发现签名会改变可执行文件摘要，而重新写入摘要又会改变签名输入。当前包身份文件和整包签名还未形成可部署的组合。该预检拒绝了二进制与身份不匹配的副本，证据保存在 `.artifacts/update-installer-ownership-mac-chg1wg/desktop.log`。正式签名和公证仍待推进。

## 安装和回退完成后的清理

GPT-6.2 Sol 在已有原生更新证据中核对到，回退后的解包候选占约 617 MiB。新流程在写完安装收据，并确认新版就绪或旧版启动后，才回收已完成事务。安装器退出后，由事务目录外的 Node 清理剩余文件。安装成功会回收已用的 ZIP，回退会保留经签名校验的下载供离线重试。安装中断或收据写入失败时仍保留恢复入口和所需文件。

清理遇到 ZIP 锁定会保留签名清单与事务依据。再次检查更新时可重试已标记完成的清理，并移除同一签名渠道及平台中已安装版本或更早的有效缓存。没有完成标记的旧事务保留原状。

本轮真实子进程回归覆盖正常完成、自动回退、安装中断、终态收据写入失败及归档暂时锁定。旧版本签名缓存及不可信清单分别验证。Rust 127 项通过，1 项辅助进程入口按设计忽略，Windows x86_64 MSVC 交叉检查通过。

在 macOS 原生设置页，通过回环更新渠道完成两次临时签名包测试。正常安装将 `0.1.0` 更新到 `0.1.1`，事务目录、恢复入口与已用 ZIP 消失。新版后台故意退出时，安装器恢复 `0.1.0`，事务目录和解包候选消失，原归档 SHA-256 保持一致。随后让回环渠道返回 HTTP 503，窗口仍从本地归档显示安装入口，归档请求次数保持为一次。两个窗口均读取到原会话草稿、最终安装状态，并观察到应用、后台和安装相关进程结束。

源码为 `31f0b9c`。两个安装结果均通过包内 Node、实际 PTY、Hive HTTP/SQLite 和退出冒烟。证据在 `.artifacts/update-settled-reclaim-RAtFjw/`，汇总为 `native-rollup.json`，离线重试辅助功能记录为 `window-broken/offline-retry.ax.json`。Windows 原生验收脚本已增加事务回收及归档保留断言，仍待在 Windows 运行。没有调用模型、发布或替换用户的应用。

## 更新下载被强制中断后的重试

旧版在真实回环服务流式下载时被强制终止，重试成功后仍留有旧半包。`b6f1ff5` 在检查更新及开始下载时回收已退出下载进程留下的半包和临时签名清单，保留仍活跃的下载。没有进程归属的旧格式半包保持原状。源码及包内回归以真实 Node 子进程、签名清单、回环 HTTP 和磁盘文件验证活跃下载保护、退出后回收及完整归档校验。

从 macOS 原生设置页下载一份通过临时 Ed25519 清单签名的测试更新。第一轮写入 8 MiB 后强制终止该窗口所属的 Node 后台，确认实际文件保留。重开原会话，在设置页再次检查时旧半包清除。下一次下载完整的 149,459,615 字节，归档 SHA-256 与签名清单相符，窗口提供安装入口，原草稿保留。故障轮的桌面正常退出，后台已被终止。重试轮收到后台关闭确认，记录的进程均已退出。

证据在 `.artifacts/update-download-recovery-cMFaYJ/`，包括旧版失败日志 `baseline.log`、`update-native/receipt.json`、原生窗口状态、`packaged-receipt.json`、严格签名及解包清单。macOS ZIP SHA-256 为 `53be20a4272effec2c802f1e6f589d3da67d1b607dca373d8c1891e6be92b23c`。包内下载及安装两项专项、实际 PTY 与 Hive HTTP/SQLite 冒烟通过。

从该 ZIP 中的 `0.1.0` 应用和两份已验签的 `0.1.1` 测试归档复验整个更新流程。正常归档由设置页安装后，实际重启为 `0.1.1`，设置显示安装成功，已用归档和安装事务回收。故障归档的后台在启动时退出，安装器将实际可执行文件恢复为原来的 `0.1.0`，新窗口显示回退结果。回环渠道随后返回 HTTP 503，设置仍提供基于本地归档的安装入口。两轮均保留同一会话的原草稿，安装前收到对应的后台退出确认，并核对所有进程最终退出。两个最终安装都通过各自版本的便携包冒烟。记录见 `mac-update-replay/` 和 `actual-window-rollup.json`。Windows 本轮完成目标交叉编译，原生更新仍需运行证据。
