# 内置 Pi 的 1Password 凭据

在「设置 → 模型与接口 → 配置 1Password」中选择已保存的自定义提供商，核对接口地址后关联 `op://保险库/项目/字段`。这个入口支持默认内置 Pi 配置目录中的 OpenAI Responses 和 Chat Completions 兼容接口，地址需使用 HTTPS 或本机回环。安装 `op` 并启用 1Password 桌面应用集成后，可用同一入口更换或移除引用。已经配置其他认证的接口继续使用原有设置。[1Password 字段引用](https://www.1password.dev/cli/secret-references) · [`op read`](https://www.1password.dev/cli/reference/commands/read)

Hive 保存引用和经过确认的接口配置指纹。读取设置、打开历史和刷新模型时不会调用 `op`。准备发送时，后台按需读取凭据，同一回合复用，下一回合重新读取。读取失败时保留原队列输入。接口配置发生变化时，需要重新确认引用。取消和退出时终止并回收仍在运行的 `op`。密码库凭据不会写入 Pi 默认配置或 Hive 引用文件。使用密码库的回复按完整消息显示，以便处理跨流式片段出现的原文凭据。

原生测试还发现，刷新模型后重新选择当前模型时，Hive 可能保留原先不可用的模型记录。显式选择现在会在有需要时同步 Hive 的会话记录，冷重开读取持久化的选择。

## 本轮验收

- 使用真实 Pi SDK、受控 `op` 可执行文件和本机回环 HTTP 验证 Responses 和 Chat Completions。覆盖引用校验、读取失败后恢复队列、轮换、401 错误和跨流式片段的凭据回显、读取前及读取期间的接口变更、取消、退出、冷恢复和原文检查。源码与本地 macOS 包内检查均通过。
- 在 macOS 本地开发包中，通过原生设置保存引用，关闭后重开验证引用状态，刷新并选择模型，发送一条消息，再回到设置移除引用。回环服务收到预期授权请求，两个桌面进程以 0 退出。日志、包摘要和收据保存在 `.artifacts/pi-vault-mac-3uFbP3/`，其中 `ui-Jne3D4/receipt.json` 对应原生流程，`packaged-vault-final.log` 对应包内凭据回归。
- Rust 测试 114 项通过，1 项辅助进程入口按设计忽略。Windows MSVC 交叉检查通过，原生 Windows 验证及真实 1Password 账户授权仍待实测。本机测试未安装 `op`、未登录 1Password、未向厂商调用模型，也未改动全局模型或账户设置。没有发布。

## 读取期间移除引用

旧后台在 `op` 仍等待读取时接受了移除引用的设置变更。延迟结束后，模型接口依然收到了旧请求。现在移除或更换已保存的引用会取消对应的待读取。后台在取凭据前后核对已保存的绑定，也在交给模型请求前重新核对绑定和接口。已经发出的网络请求按原有生命周期结算。

在解包后的 macOS 应用里，先使用受控 `op` 让一条消息停在凭据读取，再从设置移除引用。待读取的进程退出，回环接口收到零个请求。退出重开后，原消息正文和重试入口仍在。绑定另一条引用并点击重试，回环接口恰好收到一条含新凭据和原消息的请求。三个桌面进程及记录的后台均以正常流程退出。

源码和包内 Pi vault 专项通过，覆盖 Responses、Chat Completions、过期配置、移除、重新绑定、取消和退出。macOS ZIP 复用 `b4dfbc0` 的原生程序及同一份 Node，后台来自 `e20b882`。严格签名、解包清单及便携包冒烟通过。真实 1Password 账户和 Windows 原生流程仍待验收。
