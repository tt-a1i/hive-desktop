# Codex 原生历史分叉与代码检查点

本批为源码集成和受控协议验收，尚未纳入 current/candidate 开发包。没有运行真实 Codex CLI、真实模型、账号登录或图形界面验收。首片是“分叉 / 编辑并分叉”；原地历史回退另行实施。

## 行为

已保存、原始归属可信的 Codex 会话可按完整原生分页中的用户条目选择边界。普通分叉保留所选完整回合；编辑分叉保留该用户输入之前的历史，把原文和可恢复附件保存为子会话的未发送草稿。首回合编辑仅在新子线程上调用原生 revert，原线程始终不变。多用户输入同回合等无法证明精确边界的情况拒绝操作。

用户明确选择动作时的当前代码，或该源会话已保存的代码检查点。界面标明历史对话与代码来源分别是什么。私有原始字节快照分别记录 HEAD、索引和磁盘内容，在新专有工作树重建；忽略文件留在原目录，不复制到子目录，也不强制写入 Git objects。当前实现要求项目目录就是仓库根；不支持的文件系统/索引/过滤器状态明确拒绝。

创建和打开分叉不会绑定成员、启动原生 Agent、发送草稿，或复制 Hive 派单、消息、完成状态和 outbox。成员原始身份保持不变。子会话原生上下文包含继承对话，但桌面执行上下文和完成凭据不继承；下一次明确发送时注入新执行目录的指导。每条继承工具记录仍解析到真正产生它的原会话，多层分叉保留原来源。缺失来源不会使用子目录同名文件。

新工作树会捕获当时的项目初始化脚本，但打开分叉仅保存 pending 状态，不执行脚本；用户可在现有初始化入口明确运行或跳过，再继续 Agent。

## 并发、失败与恢复

执行门禁采用进程内全局保守范围，覆盖关联或尚未识别仓库的所有工作区。原生启动、排队投递、Git、项目脚本、现有终端输入、HTTP shell 和工作流共用准入；已有 Agent、终端、脚本、待发输入、未结派单或交互会阻止分叉。Hive 自动队列在租约期间不领取，明确 HTTP 输入在入账前返回冲突。释放后恢复排队投递。

这不能锁住外部编辑器或独立 Git 进程。快照与发布前后使用代码版本、目录清单、内容、索引、HEAD 和 Hive ledger 版本复核；发现变化则保留原数据和未发布目录并拒绝操作，不承诺操作系统级原子快照。

操作 requestId 在 checkout 和原生请求前持久独占保存。相同请求优先返回原操作，包括冷启动和源目录已不可用时。原生请求已发但没有可信 childId 时保持 uncertain，不自动重试 fork 或 revert。若 childId 已持久保存，用户可明确“核验并恢复分叉”：只读核对原线程、子线程精确前缀、原成员、ledger 和目标快照，通过后发布同一子会话；不发第二次原生修改。部分文件重建、无可信 childId、外部改动等情况保留供人工核对。普通工作树恢复入口不能接管分叉操作。

原生修改门槛目前限定初始化返回 `codex_cli_rs/0.169.0` 的已知协议，并显式传 `deferGoalContinuation:true`。其它版本会拒绝。生产安装实例仍需真实协议、Terra、原生界面和平台验收。

## 验证

`pnpm --filter @hive-desktop/runtime check:history` 包含：

- 真实 Hive HTTP / SQLite 与真实临时 Git，受控独立 JSONL Codex 进程；完整分页、精确包含边界、首条编辑、普通编辑、未发送附件草稿、忽略文件与 HEAD A / index B / disk C。
- 被动打开不发 `thread/start`、`thread/resume`、`turn/start`，初始化脚本标记不存在；Hive ledger 和源代码/索引不变。
- 冷启动原 requestId 重放、源目录缺失仍查询原操作、原生 fork 响应丢失、已知 child 的保存失败恢复、首条编辑 revert 响应丢失；恢复不追加 fork/revert。
- 多层工具来源、成员身份、专有工作树发布及普通恢复拒绝；终端、输入/派单入账前门禁，工作流与队列领取边界。

检查点专项 `check:code-checkpoints` 另覆盖特殊文件、嵌套规则 FIFO、损坏内容、限制和冷读。Git 初次仓库发现可能读取特殊配置文件仍是已知边界；预检也会保守拒绝某些已忽略目录中的特殊规则文件。

Rust 界面已通过独立目录 `cargo check` 和草稿/恢复操作专项单元检查。真实 GUI、Terra、Windows 原生、打包和完整验收尚未完成。队列门禁的定向恢复测试使用内存端口并显式 drain；持久 SQLite outbox 在释放后自动恢复的竞态实证仍需补充。
