# 原生 Codex 到官方 ACP 的真实文本接续

在 macOS 本地开发包中，以生产 JSONL 运行 [#53](https://github.com/tt-a1i/hive-desktop/issues/53) 的接续流程。软件使用 Codex CLI 0.169.0 和官方 Codex ACP 2.6.0。运行时检查两端的原生线程、执行目录、模型和厂商，实际推理均为 `openai/gpt-6.1-terra`。

- 来源 Codex 会话先收到并回复随机标记。Hive 提示有运行时不能交接，停止来源之后才允许预览和创建。创建保持原会话、原配置、Hive 协作账本及来源文件。目标的私有工作树保留相同 HEAD，并分别物化了内容不同的暂存区和磁盘文件。重复提交同一请求返回相同目标。
- 创建和打开目标时没有启动 ACP，首条普通输入才启动。ACP 在独立原生会话中收到一次交接内容，并回复了输入正文里没有的随机标记。macOS 窗口冷启动显示来源、已消费状态和目标回复，打开期间没有启动 ACP。关闭窗口后后台正常退出。

首次冷启动后继续发送时，官方 ACP 恢复了相同原生会话。原交接包只发送过一次，但这次请求的 Hive 自动恢复摘要包含来源会话的旧用户输入。修复后，有接续来源的会话在生成恢复摘要时跳过工作区近期聊天，保留任务、成员、派发消息和待答问题。普通会话沿用原恢复规则。此前实际发给原生会话的提示仍是原始历史的一部分。

修复后的开发包再次冷启动同一目标，使用实际 `session/load` 继续会话。观察到一条新提示，交接包、来源标记和近期聊天摘要的出现次数均为零。Terra 返回了新输入要求的标记，原有回复和已消费状态也可读取。一次测试脚本误用旧回合计时导致提前退出，在实际推理前留下待核验投递。复验经产品的精确投递 ID 丢弃入口移除了该测试等待项，再发送了新的显式输入。测试记录共四次真实模型回合，全部隔离运行。原生工具只执行了不刷新的账号状态检查。

证据位于 `.artifacts/native-acp-handoff-mac-iwxpps/run-hBkuwm/`。首次接续见 `receipt.json`，修复前请求见 `continued-after-cold-receipt.json`，修复后的真实续聊见 `fixed-continuation-receipt.json` 和 `5.observer.jsonl`。修复包再次通过实际窗口冷读和正常退出，见 `fixed-cold-window-receipt.json`。两版包内恢复摘要对照确认普通会话的内容逐字一致，接续会话只省略近期聊天段。对照日志、本地开发包与签名摘要在上一级目录。Windows 原生端及其他后端组合仍待分别验收。
