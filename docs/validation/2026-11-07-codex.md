# Codex 原生会话与团队执行验证

这是完整产品目标中的外部后端接入记录，不代表所有配置、审批交互、平台和安装包已完成。

## 原生接口与边界

实际执行器是 Codex CLI 0.166.0 的 `app-server --listen stdio://`。Hive 通过 JSONL 请求会话、模型、输入与中断，注册原生动态 team 工具；没有 Pi 转述或终端文本解析。下列成功模型验证显式使用 `openai/gpt-6.1-terra`，没有 Magpie、全局模型默认或认证配置变更。一次失败的检查违反了模型选择约束，见下文审计。

当前机器 PATH 首先找到旧版 `/opt/homebrew/bin/codex` 0.46.0，不能运行所需协议。验证通过 `HIVE_CODEX_COMMAND=/Users/tsk/.npm-global/bin/codex` 选择已安装的 0.166.0，不静默安装或替换用户 CLI。桌面配置入口仍需完善。

Codex `thread.id` 单独保存为 `codexThreadId`，不是 Pi 会话文件。新原生线程在首次输入前还没有可恢复 rollout；适配器仅在原生回合建立后保存持久线程绑定。隐藏 Hive 上下文独立保存，通过 `turn/start.additionalContext` 发送给模型，显示记录不回灌模型。

安装版本虽然生成了分页历史接口的 schema，实际 `thread/items/list` 返回“不支持”。接入显式使用 legacy history；该接口还会遗漏动态工具并重建消息 ID。因此桌面持久保存仅用于显示的原始事件记录，保留实时 ID 和工具详情。缺失显示记录时会明确标注历史导入或缺口，不将重新构造的 ID 伪称为实时 ID。

## 真实验证

- `packages/runtime/.artifacts/codex-session-1793990313196`：模型读取随机隐藏标记，实际调用动态工具；重开后回调继续工作，更新隐藏上下文生效；模型设置、真实中断和继续成功，重开保持消息 ID 和工具历史。
- `.artifacts/codex-team-live-hxlKIf`：Codex 主控用 team 创建 Codex Worker，模型继承 Terra；Worker 创建文件，精确内容为 18 字节 `HIVE_TEAM_TERRA_OK`，读取派单消息后显式汇报，主控独立核验并返回完成标记。两个原生线程身份不同，关闭整个 Hive runtime 再打开后，双方 thread ID、显示消息 ID 保持一致，均为空闲。派单是 `reported`，`delivered_at` 为空，不声称验证了 delivered 状态。
- `checks/codex-runtime.ts`：真实 Hive HTTP、SQLite、team CLI 和原生 Codex app-server 的非模型集成；检查后端继承、派单、seen/report、待处理持久化、空线程处理及旧 Pi 索引兼容。
- `checks/codex-transport.ts`：实际 CLI 的初始化、模型元数据、RPC 错误、关闭回收、意外退出和缺失命令检查，无模型调用。
- `.artifacts/codex-runtime-lifecycle-terra-passed`：真实终止本次检查直接拥有的原生 Codex 子进程，验证 idle 与持久待处理两种状态下的 Hive run 退出、token 撤销、句柄回收和重新打开。该检查暂停队列调度，没有安排模型回合。
- macOS CUA 验证新建 Codex 会话、从原生模型列表选择 Terra、重开空会话以及实际回复 `UI_CODEX_OK`；含 Hive 标签的用户粘贴文本显示为“你”，恢复提示单独显示，工具历史保留。

## 失败与独立复核

首次团队检查 `.artifacts/codex-team-live-DMLuMI` 已完成实际协作，但检查错误地要求每条原生消息带 Pi 特有的 model 字段。失败收据保留；修正为核对实际选定模型及成员继承，后续完整运行通过。适配器没有补造模型字段来满足检查。

独立复核发现持久线程绑定失败后不重试、后端退出后工具仍运行：已修复为新回合前重试绑定、退出时取消并等待实际工具清理。`checks/codex-session-failures.ts` 使用真实 Node 子进程的合成协议端验证这两个故障时序；它没有调用模型，也不冒充原生 Codex 的故障实测。独立复跑通过。

另一次复核发现更换已有成员配置后仍启动旧后端、原生进程死亡后 Hive run 仍存活：现显式拒绝与既有会话不兼容的后端重启，保留原 transcript，用户需创建/选择对应后端会话；同一后端的显式模型配置会应用或报错。意外进程退出进入 Hive 生命周期清理，重新打开会创建可用句柄。

模型约束违规审计：首次失败的生命周期检查为了测试模型切换选了 `openai/gpt-4`，Hive 恢复流程可能尝试发出请求。该版本检查的 finally 删除了临时记录，无法证明是否实际推理；不能称为无模型调用或 Terra 验证。审计保存在 `.artifacts/codex-lifecycle-model-audit/receipt.json`。已删除替代模型选择路径，成功版本在每次激活/恢复前显式配置 Terra，并保留后续失败证据。

Codex 的命令审批、文件变更审批和用户补充输入交互及其验证边界见 [交互验证记录](2026-11-07-codex-interactions.md)；其他未知请求不会被自动批准。混合后端团队、全部厂商事件、Windows 真机及分发包仍需继续验证。模型工具的副作用与投递完成标记之间仍存在中断窗口，不保证 exactly-once。
