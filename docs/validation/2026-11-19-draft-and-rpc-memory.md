# 草稿附件及后台响应的内存生命周期

桌面端将已解析的后台响应交给调用方，省去对完整结果的额外复制。大型历史或附件响应解析后立即释放原始通信缓冲。较小的缓冲留给后续消息复用。

只有当前草稿保留解码后的图片预览及原图。切换草稿、移除附件或断开后台时释放不用的图片与原生渲染资源。持久化附件引用照常保存，回到草稿时从后台恢复预览。快速切换时，后台预览读取最多两个同时进行，已经离开或移除的附件不会被迟到的读取放回缓存。

Rust 115 项测试通过，1 项辅助入口按设计忽略。实际解析约 6 MiB 的 UTF-8 历史响应后，测试确认原始缓冲容量降为零，并能继续解析下一条响应。Windows MSVC 交叉检查通过。

macOS 本地原生包从 160 条历史和一张 3,241,953 字节 PNG 的草稿切到另一草稿，再切回。两个草稿的文字保留，原附件引用保持相同 ID，RPC 日志显示首次打开和切回时各读取一次图片。应用确认后台关闭后以 0 退出。包摘要、窗口树和过程收据在 `.artifacts/draft-memory-mac-ekeJBy/`，包括 `switch-receipt.json` 和 `native-rpc.log`。尚无 Windows 原生窗口或整体进程常驻内存的对照测量。没有发布。
