# 长历史的 Markdown 渲染内存

打开会话时只为 GPUI 列表实际渲染的助手消息创建 Markdown 视图和解析任务。滚动后释放离开渲染范围的视图，保留正在使用键盘和文本选择的视图。切换会话时释放整组视图。消息正文和 ID 继续由会话持有，供查找、定位、复制与导出使用。

在同一台 macOS 机器，用 `f2d8dc4` 本地开发包和本次改动后的开发包分别打开一份 1,200 条助手消息的隔离历史。两包使用相同后台和依赖，每个步骤稳定后采样桌面进程 RSS 五次，取中位数。

| 窗口状态 | 改动前 | 改动后 |
| --- | ---: | ---: |
| 首次打开长会话末尾 | 306.5 MiB | 163.9 MiB |
| 切换到空会话 | 303.1 MiB | 156.1 MiB |
| 切回长会话末尾 | 309.3 MiB | 163.2 MiB |

改动后实际使用会话内搜索定位第 5 条消息，跳回末尾，切换到空会话，再切回长会话。两次进程均正常退出，已观察的后台进程均退出。测试使用隔离的本地历史，未发起模型请求。数值来自一轮调试包对照，整体内存随历史内容、平台和使用方式变化。

Rust 单测 115 项通过，1 项辅助入口按设计忽略。Windows MSVC 交叉检查通过，Windows 原生窗口、便携包和内存仍需实测。两次屏幕无障碍树、RSS 采样和退出收据位于 `.artifacts/markdown-memory-mac-Qar9XE/` 的 `before/` 与 `after/`。

## 隐藏当前会话时释放渲染资源

GPT-6.2 Sol 复查发现，团队等页面替换对话列表后，旧版保存着该会话的 Markdown 渲染对象。在窄窗侧栏覆盖对话时，旧版还保留已按需加载的历史图片。`b0450f4` 按对话列表实际是否显示释放 Markdown 视图及解析任务，取消已隐藏的图片加载并释放图片资源。原会话、草稿和消息列表状态继续使用。

使用 250 条助手消息和 6 张历史图片的隔离数据，在本地签名的 Mac 优化包中对照。两版都进入团队并返回，再在 760 像素宽窗口用同一快捷键打开、关闭全屏侧栏。两个流程都保留末尾消息和未发送草稿，每次运行只打开一次原会话。关闭侧栏重新显示历史时，旧版使用未释放的图片，新版仅发起一次按需图片请求，侧栏覆盖期间没有图片请求。

每个状态稳定后采样五次，取 Rust 桌面进程 RSS 中位数。旧版打开窄窗侧栏前后均为 142.3 MiB，新版从 141.1 MiB 降到 134.5 MiB，下降约 6.6 MiB。团队页切换验证了可返回同一会话，RSS 采样没有观察到独立下降。两版正常退出，记录的 Node 子进程均已退出。

原生辅助功能树、后台图片请求、RSS 和退出记录在 `.artifacts/update-download-recovery-cMFaYJ/memory-baseline/` 与 `memory-candidate/`。macOS 优化构建、129 个 Rust 测试、窗口生命周期和签名 ZIP 检查通过。Windows MSVC 目标通过编译检查，原生内存与窗口运行继续待验。
