# 长历史的 Markdown 渲染内存

打开会话时只为 GPUI 列表实际渲染的助手消息创建 Markdown 视图和解析任务。滚动后释放离开渲染范围的视图，保留正在使用键盘和文本选择的视图。切换会话时释放整组视图。消息正文和 ID 继续由会话持有，供查找、定位、复制与导出使用。

在同一台 macOS 机器，用 `f2d8dc4` 本地开发包和本次改动后的开发包分别打开一份 1,200 条助手消息的隔离历史。两包使用相同后台和依赖，每个步骤稳定后采样桌面进程 RSS 五次，取中位数。

| 窗口状态 | 改动前 | 改动后 |
| --- | ---: | ---: |
| 首次打开长会话末尾 | 306.5 MiB | 163.9 MiB |
| 切换到空会话 | 303.1 MiB | 156.1 MiB |
| 切回长会话末尾 | 309.3 MiB | 163.2 MiB |

改动后实际使用会话内搜索定位第 5 条消息，跳回末尾，切换到空会话，再切回长会话。两次进程均正常退出，已观察的后台进程均退出。测试使用隔离的本地历史，未发起模型请求。数值来自一轮调试包对照，整体内存随历史内容、平台和使用方式变化。

Rust 单测 115 项通过，1 项辅助入口按设计忽略。Windows MSVC 交叉检查通过，Windows 原生窗口、便携包和内存仍需实测。两次屏幕无障碍树、RSS 采样和退出收据位于 `.artifacts/markdown-memory-mac-Qar9XE/` 的 `before/` 与 `after/`。
