# 会话置顶验证

日期：2026-11-08。范围：项目内常用会话置顶及可靠保存，完整产品目标继续开放。

## 使用场景

主控和常用成员会话会被新会话推到项目列表下方，需要反复搜索或滚动。会话行新增“…”菜单的置顶/取消置顶，项目内置顶项始终在普通项之前，两组仍按原活动时间倒序。若不做，项目会话增多后定位常用会话的操作成本持续上升。

参考已取得的 Cindy 固定快照 `4fd670b72af9d060785e29c553a14b6794dfe8eb` 的会话置顶操作。本轮实现项目内排序，尚未实现 Cindy 的跨项目独立置顶区，不据此宣称完整体验对齐。

## 后台与界面

- 沿用 ChatIndex 元数据文件，增加可选 boolean pinned，旧记录默认未置顶。无 SQLite schema 或 Hive 协议变化。
- chat.pin 严格校验布尔值，重新读取当前记录，只改 pinned；保留标题、后端、Agent/原生会话身份、历史路径和 updatedAt。关闭/移除期间沿用现有拒绝边界，相同状态重复提交无需写盘。
- 文件写入成功后才替换内存；补齐已有索引写入失败后的临时文件清理。生产接口返回已保存记录及该项目的权威排序列表。
- UI 在响应成功后更新对应项目列表，不打开其他会话、不清空聊天或草稿；请求期间阻止同一会话重复提交，失败显示错误并保留原状态。后台重启清除未决的 UI 标记，响应受连接代数约束。
- 重命名响应只合并标题字段，避免整条旧快照覆盖独立的置顶属性。会话可访问名称包含已置顶状态。

## 验证证据

`pnpm --filter @hive-desktop/runtime check:session-pins` 通过。真实 Hive HTTP/SQLite、ChatIndex 文件和生产 Node JSONL 覆盖：

1. 四种后端空记录的置顶/取消、排序、重复设置和元数据保持。
2. 不同项目隔离、名称修改保留置顶、旧记录兼容、无效持久字段拒绝、无效参数/未知 ID 不改文件。
3. 用目录占据 index.json 触发真实写盘失败，验证原内存和保留文件不变，临时文件清理，恢复后可重启。
4. 后台重新启动后状态与排序保持；生产 JSONL 再次置顶/取消后由新索引读回。没有初始化 Agent 会话、写入 Agent 历史或发送模型请求。

既有 `check:team` 通过，包含真实协作派单/汇报队列、名称和跨项目搜索回归，不发送模型请求。Mac 生产构建、格式检查与既有 Rust 检查通过（15 passed，1 ignored）；完整默认特性的 Windows MSVC 目标类型检查通过。元数据改动不涉及执行协议或数据库迁移，未重复全量 Node suite。
