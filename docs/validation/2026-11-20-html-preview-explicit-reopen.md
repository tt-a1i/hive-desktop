# HTML 预览的显式快照重开

Windows WebView2 156.0.4314.58 在取消子框架导航后可能显示白页。此前回放 `44589072389` 的原始 UIA 树保留外层 `RootWebArea` 和 `HTML artifact` 框架，内部变为 `127.0.0.1` / `sub-frame-error`。这份证据支持在可信外层文档提供恢复操作，不证明原页面 JavaScript 状态能够保留。

预览现在始终显示“从快照重开”。点击后先提示“重开将重置页面内未保存的输入和交互状态”，用户可取消或确认。确认后，只从外层闭包捕获的原始 `srcdoc` 重新初始化同一个沙箱框架。它不会重新读取源文件或重新捕获快照。原有预览窗口、来源身份、临时网页存储的生命周期和关闭行为保持。

`allow-scripts` 沙箱仍使用不透明来源。页面没有 IPC 或宿主文件入口。顶层文档仍只供应一次；窗口及子框架的导航取消、资源拦截、CSP、权限、弹窗、下载和宿主 API 限制保持。恢复操作不取消任何安全检查，不自动跳转，也不依赖网页提供的消息。

## 验收的含义

Windows 原生脚本分别记录 `DirectDocumentAndStateRetained` 与 `ExplicitSnapshotReopen`。前者仅在导航后直接找到原文档标记及计数 1 时为真；未观察到则记录为假并保留截图和 UIA 树。显式重开的通过不会被计为直接保留页面状态。

首次打开和源文件已移除的冷启动都要求：初始隔离标记和文件选择限制通过；计数变为 1；取消重开仍保持 1；尝试被拦导航后，外层按钮仍可找到并实际调用；确认重置后，隔离标记、文件选择限制及计数 0 → 1 通过；预览原窗口句柄保持。原有回环服务零请求和进程退出断言保持。脚本输出 `windows-html-recovery-initial.json`、`windows-html-recovery-cold.json` 与各阶段诊断。

## 本地检查及边界

从实际 Rust `frame_document` 函数生成页面，使用本地 Chromium 检查了二步提示、取消时计数和未保存输入保持、源文件删除后从内存快照重开、同一 `srcdoc` 再次赋值仍重置计数和输入，以及重开后按钮继续工作。测试驱动曾将框架内容替换为普通“不可用文档”夹具，以检查外层操作及捕获快照的独立性。这不是 Windows 原生导航复现，也不代替 WebView2 的导航/网络隔离验收。

本地原始快照位于独立工作树 `.artifacts/html-reopen-local/reset.snapshot.txt` 和 `continued.snapshot.txt`。Windows 原生恢复及按钮可达性仍须用含此改动的新可执行文件验证；未替换用户安装、未发布。

macOS 原生窗口在首开和冷开均验证了同一 AX 窗口内取消保留、确认后重置、源工作树已移除及正常退出。字段值由页面中的测试按钮写入。另用真实 HID 鼠标操作，预览处于前台且点位在文本框 AX 边界内，但未观察到字段焦点；同一签名包的主窗口搜索框在相同驱动下可获得焦点并输入 g。同一签名包的后续真实 HID 实测在首开与移除源工作树后的冷开均成功：预览置前并稳定 600 ms 后，真实鼠标点击文本框，键盘输入 g；取消保留字段和计数，确认后同窗重置并可继续操作，两次后台正常退出。此前一次焦点失败未稳定复现，原因未确定。
