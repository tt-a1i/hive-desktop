# 历史图片按需加载

桌面打开会话时使用带图片引用的聊天快照。快照保留完整文本、图片数量、消息 ID 和编辑所需的原生身份。图片数据留在后台历史中。消息进入 GPUI 列表渲染范围后，桌面按工作区、会话、消息 ID 和图片序号读取，限定同时读取的消息数量。离开渲染范围后，桌面取消该消息未完成的读取并释放原图和缩略图。已打开的图片查看器单独持有正在查看的原图，关闭后释放。

测试在 Mac arm64 的两个本地签名开发包进行。两包使用同一份后台代码，分别用改动前后的桌面程序打开相同内容的隔离 Pi 历史，包含 48 张生成的 PNG。末尾缩略图可见后，对桌面进程各采样五次 RSS，取中位数。

| 观测项 | 改动前 | 改动后 |
| --- | ---: | ---: |
| 冷开会话的 JSONL 响应 | 235,740,812 字节 | 182,991 字节 |
| 末尾窗口桌面 RSS | 382.4 MiB | 157.0 MiB |

在新包用会话内查找定位到第一张图，核对查看器显示的 848 × 569 尺寸，并通过系统保存面板导出原图。导出文件与测试原图逐字节相同。回到末尾时实际重新读取缩略图。Markdown 原生导出完整记录了 48 张图片的数量，并保留首尾正文。切换到空会话后重开，末尾原图仍显示正确的 992 × 684 尺寸。两包均正常退出，后台确认关闭，记录的子进程均已退出。

独立包内 JSONL 检查对照了默认的完整响应和桌面使用的新响应，核对了相同收录范围与消息 ID、按需读取原始数据，以及对错误工作区、会话和图片序号的拒绝。类型检查、图片附件专项、Rust 测试与 Windows MSVC 交叉检查通过。原生运行使用隔离历史和本地文件，未请求真实模型。

本次数据只代表这组 macOS 调试包和图片。RSS 采样衡量桌面进程。文字历史仍完整载入，后台在需要时仍读取本地原生历史。Windows 原生窗口与内存有待实测。证据位于 `.artifacts/history-image-window-P6hvby/` 的 `receipt.json`、各阶段日志和 `after/project/history-image-counts.md`。
