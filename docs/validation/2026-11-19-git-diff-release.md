# Git 面板打开、内存释放与本机推送

原生 macOS 开发包点击 Git 状态入口时，GPUI 因子视图在主窗口更新期间尝试读取主窗口而中止。首次加载与重开改在主窗口更新完成后执行。关闭面板或切换到远端时释放原始文件补丁和结构化差异，迟到的响应不会重新装入。重开重新读取同一文件及比较方向，提交说明与已审查的远端操作仍由原面板保留。补丁从响应转移到桌面状态，原始视图复用同一份字符串，结构化视图不再构造原始展示文本。

## macOS 内存对照

使用两个本地临时签名的 arm64 开发包、同一包内 Node 和独立 Git 仓库。两个仓库各有 22,000 行替换，Git 生成的补丁约 473 KiB。原始版本会崩溃，对照包仅修复打开时的崩溃，保留原有内存行为。两次试验均从同一 Git 面板路径查看结构化差异，再用关闭按钮隐藏面板。

| `vmmap -summary` 默认分配区活动堆内存 | 加载差异前 | 展开差异 | 关闭面板 |
| --- | ---: | ---: | ---: |
| 仅修复崩溃 | 17.2 MiB | 38.4 MiB | 38.1 MiB |
| 同时清理补丁与差异 | 17.5 MiB | 38.7 MiB | 18.6 MiB |

修复版关闭后释放 20.1 MiB 活动分配。物理内存占用在此次短测中没有随关闭立即下降，分配器保留了空闲页。

## 原生工作流程

- 通过窗口按钮打开变更列表并查看结构化及原始补丁。关掉面板后修改磁盘文件，按快捷键重开，原文件自动重新加载并显示新内容。
- 通过原生窗口审查并暂存小文件，关闭并重开面板后确认提交说明与暂存补丁还在。提交只包含该文件。大文件继续留在未暂存区。
- 对本机裸仓库预览推送内容，关闭并重开后保留相同目标和固定提交。确认推送后，直接读取裸仓库的 `refs/heads/main`，与工作区 HEAD 完全一致。最终签名包再走一次暂存、提交和推送，辅助功能树可读取提交与推送回执。
- 对照包和两份修复包正常退出，后台均确认关闭，未留下本轮验收进程。未调用模型。本次推送仅写入本机测试仓库。

## 暂存提交补丁按需读取

优化包 `526926a` 打开提交预览时只读取暂存路径、提交检查与版本。展开补丁才运行 Git 生成完整补丁。隐藏补丁或关闭面板会释放 Rust 持有的补丁。关闭前处于展开状态时，重开按同一版本重新读取。提交确认仍核对 HEAD、暂存区与提交配置。

macOS 原生窗口对照使用两个隔离仓库，两份 Git 补丁逐字节一致，共 1,839,619 字节。每个状态采样三次，表中为桌面进程默认分配区活动堆内存的中位数。

| 应用 | 打开文件清单前 | 预览提交清单 | 展开补丁 | 隐藏补丁 | 关闭面板 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 上一优化包 `87c898e` | 17.1 MiB | 18.3 MiB | 173.8 MiB | 20.7 MiB | 20.5 MiB |
| 按需读取 `526926a` | 17.4 MiB | 17.7 MiB | 174.6 MiB | 19.7 MiB | 19.3 MiB |

新版本关闭面板后的活动堆比对照低 1.2 MiB。展开大补丁时的峰值仍高，两版接近。物理内存短时读数有波动，表中数据只代表此次活动堆测量。

- 两次在窗口展开同一份补丁后保留提交说明。关闭面板并从原生 Git 更新暂存内容，重开后窗口拒绝读取旧补丁，显示原因且禁用确认。重新预览后提交成功，Git 独立核对新提交的文件内容、原提交说明和另一文件的未暂存改动。
- 用实际 Git 进程延迟补丁读取。首次查看清单时没有执行补丁命令。窗口在读取时隐藏补丁，后台随后完成请求，迟到的响应没有重新显示。再次展开时发起新的读取。三次运行关闭后均收到后台退出确认，桌面与后台进程都已结束。
- Rust 测试 121 项通过，1 项辅助入口按设计忽略。真实 Git 索引、JSONL、写入生命周期及解包后的索引回归通过。macOS ZIP 解包验签、应用树比对及包内 Node、PTY、Hive HTTP／SQLite 和退出冒烟通过。Windows x86_64 MSVC 交叉检查通过，当前版的 Windows 原生窗口和内存实测仍待验。没有发布或替换本机安装，也没有调用模型。

证据位于 `.artifacts/staged-patch-lifecycle-yX6sHz/`。包括 `receipt.json`、三个原生流程的辅助功能树和日志、内存采样、`packaged-index-wire.log` 及 ZIP 校验摘要。

## 大补丁的原生分页

优化包 `bea6faa` 对暂存补丁和文件原始 Diff 使用同一个分页阅读器。每页最多排版 32 KiB 和 256 行。超长单行在 UTF-8 字符边界处分开。每页支持文字选择，跨页可用“复制完整补丁”。隐藏暂存补丁、关闭面板和切换文件时，阅读器随对应状态释放。

用同一份 1,839,619 字节的暂存补丁做 macOS 原生对照。两版在每个常规状态采样三次，下表为桌面进程默认分配区活动堆内存的中位数。分页版翻到第 54 页时另取得一次 22.0 MiB 的读数。

| 应用 | 展开补丁 | 隐藏补丁 | 关闭面板 |
| --- | ---: | ---: | ---: |
| 按需读取 `526926a` | 174.6 MiB | 19.7 MiB | 19.3 MiB |
| 按需读取并分页 `bea6faa` | 22.0 MiB | 16.9 MiB | 16.7 MiB |

- 通过原生辅助功能依次读取 57 页暂存补丁和 19 页原始 Diff。两份结果逐字节等于独立 Git 命令的输出。检查第一页与最后一页的按钮状态，并从末页返回上一页。在两个入口中从中间页复制完整补丁，与 Git 输出逐字节一致。验收程序恢复了打开剪贴板之前的内容。
- 关闭窗口侧栏后用 Git 更改暂存区，重开显示原预览已过期，确认不可用且提交说明保留。重新读取后提交成功。Git 状态确认另一文件的未暂存改动保留。关闭窗口后桌面和后台进程均退出。
- Rust 测试 122 项通过，1 项辅助入口按设计忽略。macOS ZIP 解包验签、应用树比对和包内 Node、PTY、Hive HTTP／SQLite 与关闭冒烟通过。Windows x86_64 MSVC 交叉检查通过，Windows 原生窗口及内存待验。没有发布或替换本机安装，也没有调用模型。

证据位于 `.artifacts/paged-git-patch-MhANWc/`。主要文件为 `receipt.json`、`after/native-check.log`、还原的两份补丁、应用树清单和 ZIP 校验摘要。
