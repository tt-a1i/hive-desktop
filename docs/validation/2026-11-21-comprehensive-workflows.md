## 运行时验证

- 导入使用三个后端各自的本地格式和受控对端。检查覆盖发现、只导入已选项目、部分失败后重试、已有会话去重、重启后重复导入、原始文件字节保持不变。显式发送后的三种后端均接回原会话。大于 9 MiB 的 Codex 记录可打开最新消息、定位较早消息并跳过已回退的轮次。Codex 初次浏览提供文本预览，工具调用等详情在原 Agent 接回后读取。
- Pi 和 Pi RPC 的 13.44 MB 测试日志分别做七次有界读，总读取约 508 KB，以单条图片 ID 读取只取 482 字节。既有 Codex 62.2 MB 测试记录的旧历史四条页读取约 50 KB。ACP 和 Codex 受控测试同时覆盖旧格式记录、保存更新及游标失效。Claude 首次为源文件版本生成展示索引，4.34 MB 测试记录重启后的两条历史页返回约 1.7 KB，且无需启动 SDK 读取进程。源文件更新会使旧游标失效。
- 普通可发送的已保存会话也走存储分页。浏览、自动读取设置摘要和按消息加载图片或工具输出不会启动 Agent。用户发送消息或主动打开 Agent 设置时可接回原会话。活跃 Agent 使用后端提供的当前历史，仍待处理的队列保留原有恢复路径。旧记录缺失身份、文件损坏或不能验证来源时继续走兼容读取路径。
- Claude 展示索引可经本地缓存清理删除。移除工作区也会清掉该工作区的索引。验证确认删除工作区后原生记录与其他工作区的索引保持可用。

## macOS 原生验证

- 空数据目录的欢迎页从两个夹具项目导入六段会话。逐一打开时，三种后端的会话都显示与源文件一致的问答。重启恢复到原会话，重复导入仍为零新增，所有源文件哈希不变。验收收据为 `.artifacts/onboarding-batch-import/receipt.md`。
- 另用隔离窗口向已导入的 Pi 会话显式发送一条输入。受控对端记录原会话 ID、原文件和工作目录，仅接收一次输入。冷启动仍可看到源记录和受控对端回复。验收收据为 `.artifacts/onboarding-pi-continuation/receipt.md`。
- 在空数据目录中打开了跨项目收件箱。两个项目中的待答复问题和等待汇报派单按优先级排列。实窗验证设定暂缓、显示和手动恢复、冷重启保留、模拟越过到期时间后重新出现，以及新问题使旧暂缓事项恢复。跨项目打开派单后，用实际请求核对历史执行会话的 ID。验收收据为 `.artifacts/cross-project-inbox-native/receipt.md`。
- 1220 像素宽的窗口中，聊天输入框与文件树同屏。实窗用方向键展开、收起、进入和退出层级，回车预览同名文件。切换独立工作树后读取到该工作树文本，迟到的原项目预览未显示。窗口缩到 900 像素后文件入口打开对话框，恢复宽窗后保留先前预览。验收收据为 `.artifacts/file-dock-native/receipt.md`。
- 在一段 360 条消息的普通 Pi 会话中，搜索命中第 151 条，定位页与更早页各取 120 条。更换夹具源文件后继续翻页，窗口阻止合并旧游标的结果。点击重新读取回到同一条消息并看到更新的文本。随后主动打开模型设置才连接 Pi，整个流程没有发送消息。验收收据为 `.artifacts/comprehensive-workflows/native-history-reload/receipt.json`。
