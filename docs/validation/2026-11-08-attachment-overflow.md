# 多附件不再撑出输入窗口

## 真实问题与变化

在 760×583 原生窗口恢复十张图片和十二行草稿，原附件区无限换行，把正文后半和发送工具栏撑到可见区域外。原生截图 `.artifacts/attachment-overflow/light-small-overflow-baseline.png` 保留了问题。

附件区现在最多占 192px，卡片保持自身尺寸并在独立区域滚动；正文和发送工具栏留在窗口内。复用现有阅读区的滚动条、Tab、方向键、翻页及 Home/End 支持，不引入依赖。切换草稿目标时回到附件区顶部，避免另一会话继承之前的滚动偏移。不改变附件数量、上传内容、草稿持久化或投递规则。

不做这一调整，用户添加多张图片后可能无法直接使用输入和发送操作；仅把普通文件变成紧凑卡片不足以解决图片附件的情况。

## 原生验收

使用隔离数据目录、真实 Hive HTTP/SQLite 上传的十张 PNG，Pi 原生会话和实际草稿文件；不是在产品代码中填充占位附件。

浅色/深色 760×583 窗口分别完成：

1. 恢复十张图片和十二行中文草稿，发送按钮保持可见；附件区最大 192px。
2. 从正文焦点用 Tab 和 PgDown 进入并滚动附件区，End 到达第二行；打开最后一张原图并在解码完成后 Escape 关闭。
3. 移除最后一张，保留九张附件及完整正文；切到空会话时附件和正文为空，返回原会话仍保留内容，附件滚动回顶部。
4. 完全退出并重新启动应用，恢复九张附件及完整草稿，再重复滚动及会话往返。
5. 点击实际窗口的发送按钮，真实投递到本地模型服务并显示其拒绝错误。每种外观仅一条本地 `gpt-6.1-terra` 请求，无厂商推理，不把本地拒绝当成模型成功。

截图、初始/重开日志和收据位于 `.artifacts/attachment-overflow/`。键盘夹具先前未建立初始焦点，图片弹窗夹具先前未等待原图异步解码/动画结束，失败日志保留为 calibration；修正这些夹具后才验收通过。原生事件、解码就绪和渲染探针仅放在独立源码副本，生产入口没有探针。

## 验证与边界

生产入口 Mac `cargo build --locked --manifest-path apps/desktop/Cargo.toml` 和完整 Windows MSVC `cargo check --locked --manifest-path apps/desktop/Cargo.toml --target x86_64-pc-windows-msvc` 通过。这次只调整 UI 布局及会话切换时的滚动句柄，不改后端协议/schema，不新增 UI 单测、不运行无关全量测试。真实原生的跨进程草稿恢复作为本批回归证据。
