# 会话归档与恢复验证（2026-11-08）

## 真实使用场景

1. 项目积累较多完成的会话时，用户的项目列表、跨项目搜索和全局置顶仍混有旧会话，查找正在使用的对话需要反复扫过历史。
2. 会话菜单可归档，导航与默认搜索隐藏旧会话；专门的归档入口支持搜索、分页和打开原记录。恢复或收到新的实际输入后，原会话返回导航，历史、草稿、成员绑定与置顶偏好保留。
3. 不做会让长期项目的会话入口持续拥挤；删除历史或重建 Agent 不能替代整理导航。

## 数据与协作边界

`ChatRecord.archived` 是桌面 index.json 中的可选布尔值，旧记录按未归档解释。归档只修改导航元数据，保留 ID、后端、原生会话引用、成员身份、标题、活动时间和置顶偏好，不关闭 Agent、不删除历史、不修改 Hive schema 或协作账本。底层 `chat.list` 仍返回全部记录，供成员绑定、恢复和工作区移除使用。

`chat.archive {sessionId,archived}` 严格校验布尔参数。写盘成功后发出带会话流序号的 `session_navigation {archived,pinned,updatedAt}`；幂等请求也发通知但不重写文件。窗口按有序通知更新当前/其他项目缓存和置顶列表，不用可能较迟到达的 RPC 回执覆盖新消息恢复的状态。回执仍验证返回会话身份、工作区及请求状态。后台重启后的旧连接结果被忽略。

归档前检查真实投递队列是否忙碌或存在待处理记录，包括冷会话磁盘队列。已绑定成员还检查 Hive 的未结派单与待处理任务；主控检查其团队。活跃但空闲的 SDK 会话可以归档，不把 Hive 中运行进程的 working 状态误判为正在生成。检查复用工作区串行屏障，HTTP 查询后重查队列和元数据。它是检查时刻的约束，不声称与其他 Hive 客户端的写入形成跨存储事务。

实际用户输入、派单或汇报在交给既有持久队列之前恢复归档会话，并更新活动时间；纯启动上下文不恢复。已经可见的会话不会因此新增索引写入。归档状态写盘失败会保留内存/磁盘原状态并提示重试；新输入尚未入队时的索引失败沿用现有投递错误路径。

默认搜索及全局置顶仅列未归档记录；归档搜索使用同一接口 `chat.search {query,archived:true,offset}`，每页最多 100 条，offset 为非负安全整数。切换查询重置分页，刷新后结果减少时回退到有效的最后一页。列表首次自动选择只考虑未归档会话，显式保存的归档选择仍可恢复。

当前归档会话保留编辑器及附件，显示恢复入口；切换项目、归档元数据通知不清空正文、不抢走其他会话焦点、不制造未读消息。全局置顶刷新合并连续请求，并跳过已被更新请求取代的结果。

## 原生与打包验证

浅色、深色和 760px 窄窗口已分别完成原生流程（每种两次独立进程，退出后重开）：

- 真实索引写盘失败保留中文多行草稿、图片附件、原归档状态与置顶；成功归档后显示恢复入口并从置顶隐藏。
- 108 条归档按 100/8 分页；恢复末页 8 条后刷新自动回退到第一页，再次归档后刷新回到 108 条。
- 输入中文搜索并按 Enter 打开，显式恢复后置顶返回；归档后切换另一项目，实际后台输入恢复原会话但不切走当前会话或抢走编辑焦点。
- 重开后原项目选择、两份独立中文草稿、图片附件与待处理消息均保留；待处理消息阻止归档。
- 只有归档记录且没有保存选择的项目不会自动初始化其 Codex 会话。

检查保留了失败证据：最初只 dispatch KeyDown 的夹具没有经过 GPUI 文本处理，已改用公开 dispatch_keystroke；随后窄窗证明 Enter 默认确认先关闭弹窗、让延迟的 PressEnter 丢失。产品搜索弹窗现禁用默认确认关闭，由 open_selected 完成导航与关闭，增强检查要求窄窗导航确实收起后才继续，修复后通过。打开期间的归档事件也改为复用现有快照回放队列，避免响应覆盖新状态；未新增独立事件存储。

截图、日志和夹具源码位于 `.artifacts/session-archives/`（例如 `light-archive-current.png`、`dark-archive-current.png`、`light-small-archive-reopen.png`）。原生检查使用 GPUI 临时渲染/AX 边界观察 hook，生产 vendor 没有新增夹具 hook。循环对端仅收到每种流程一次请求，不会在重开时再次推理；不把此处 API 400 识别为真实模型结果。

macOS 的原生夹具使用隔离数据和真实窗口布局/输入事件；不等同物理鼠标、系统输入法或 Windows GUI 验收。Windows 本地 MSVC 类型检查已通过，最新 Windows CI 仍受账户计费限制。全量 runtime 测试未运行，按导航元数据与共享投递变化运行相关归档、团队和置顶检查。
