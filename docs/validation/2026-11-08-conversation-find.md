# 当前会话内容查找

## 场景与行为

长会话中回看前文或某次工具执行时，原先只能滚动浏览，已有跨项目搜索仅匹配会话元数据。现在会话标题栏提供查找入口，macOS `Cmd+F`、Windows `Ctrl+F` 打开当前已加载消息的本机查找。

- 匹配正文、工具名、输入参数、输出及已进入会话的汇报原文，不区分英文大小写，支持中文。
- 每条匹配消息计数一次。Enter / Shift+Enter 或按钮前后循环；命中消息使用整块背景提示，不宣称逐个词高亮。
- 命中折叠工具或来源原文时展开，并用 GPUI 嵌套 ScrollAnchor 定位。
- 查询变化重新扫描；流式更新仅检查变化的消息，匹配集合变化时调整顺序。查找期间不因新回复回到底部。
- Escape 或关闭按钮返回原焦点，保留输入草稿。返回最新会关闭查找并恢复跟随；切换会话或工作区清除查找状态。
- 不做此项时，定位长会话内容仍依赖手工滚动。没有新增后端索引、模型调用、依赖或协议。

## 实际验证

使用 180 条合成消息的原生 GPUI 窗口，工作区与会话记录来自真实 Node / HTTP / SQLite；消息正文和工具结果为测试数据，不代表真实模型执行。

深色 1180×820 与浅色 760×620 两种窗口均完成：

1. 英文大小写查询匹配到中文正文、折叠工具的参数和来源原文，共 3 条；后两者的显示摘要不含查询词。
2. 实际布局中，深色窗口从底部 `-46571px` 定位到正文 `-1339.5px`，再定位到工具行 `-18545px`；工具组和详情实际展开。浅色窄窗同样通过布局与位置断言。
3. 前后循环、流式新增 / 移除匹配、中文单独查询、无匹配集合均通过。
4. 实际 `agent_event(AssistantDelta)` 增加新消息后，阅读偏移保持不变；真实输入控件编辑触发查询订阅，派发关闭 Action 后查找消失，原中文草稿保持。返回最新清除查找状态。
5. 已查看四张渲染图：`.artifacts/conversation-find/{dark-text,dark-tool,light-narrow-text,light-narrow-tool}.png`。

### 测试边界与失败记录

首轮使用正常 OS 帧调度，锁屏导致窗口未绘制，滚动范围为零，断言失败。这不是定位通过的证据。随后在临时源码副本中，仅为测试暴露 GPUI 当前场景渲染和按框架原顺序运行帧回调的方法，显式绘制实际布局。另一次夹具把 `InputState.set_value` 当成用户编辑，查询未更新；该 API 明确不发 Change，改用真实编辑 API `replace_all` 后检查通过。没有修改生产逻辑去适应夹具。

临时测试驱动、暴露的 GPUI 方法和测试数据均不进入正式应用。Mac 鼠标 / 物理快捷键操作仍因锁屏未走查；派发 Action 不等同于实际按键验收。Windows 未取得本轮真机或最新 CI 验证。查找仅涵盖当前已加载消息，不搜索其他会话内容、尚未投递汇报或外部工具生成文件；没有新增虚拟列表，也不声称长会话渲染性能已达标。
