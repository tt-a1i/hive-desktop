# 冷启动恢复会话阅读位置

桌面在滚动停下、切换会话、退出或重启后台时保存阅读位置。记录按工作区及会话区分，包含消息或工具组 ID 和行内偏移，最多保留最近 64 条。正文、图片与展开内容不写入该文件。恢复时，历史中缺失的消息 ID 会回到会话末尾。点击「跳到最新」会移除原位置，删除项目会一起移除该项目的记录。

## macOS 原生验收

在签名的 arm64 开发包中打开隔离会话。此前 `4627c87` 的原生验收中，冷启动后需要重新搜索才能返到早期命中位置。本次使用同样包含 91 条消息的夹具，搜索后在旧消息区域滚动，并写入一份未发送草稿。

- 滚动停止后，应用在退出前已经保存了 `row-1` 的 64.5 像素偏移。记录文件为 143 字节。
- 退出再启动，窗口直接在同一消息和草稿处打开。切换到另一个会话并返回后，再次核对持久记录与退出前逐字节一致。
- 点击「跳到最新」后，记录为空。再次冷启动显示最后一条消息，草稿仍在。91 条消息的 ID 和正文与原夹具一致。
- 三次运行都以状态 0 退出，均收到后台关闭确认。进程已回收，未触发消息发送、会话激活或账号 RPC。

120 项 Rust 测试通过，另有一个子进程入口按设计忽略。新增回归覆盖读取偏移、工作区隔离、移除记录与 64 条上限。macOS 包通过严格签名检查、包内 Node、真实 PTY、Hive HTTP/SQLite 与退出冒烟。Windows x86_64 MSVC 交叉检查通过，原生窗口待验。本轮使用本地开发包，没有发布。
