# 桌面安装、重启与失败回退

`d6e321a` 在“设置 → 关于与维护”接通了已校验更新的安装入口。有运行中的会话时，应用会请用户等工作结束。安装前保存草稿并确认后台进程已退出。独立安装程序再次检查新旧程序的 SHA-256，保留旧版，等待新版完成第一次工作区读取后才确认安装。新版启动失败时，安装程序恢复并重开旧版。应用数据留在安装目录之外。

## macOS arm64 原生验证

从同一源码分别构建 `0.1.0` 与 `0.1.1`。版本变化只用于隔离验收。用实际打包脚本和包内官方 Node，签名清单由本地回环服务提供。两次均从实际原生窗口检查、下载、确认安装，旧程序正常退出。同一会话的未发送草稿在每次重开后都出现在原生输入框。

| 用例 | 更新归档 | 结果 |
| --- | --- | --- |
| 正常安装 | 163,014,493 字节，`4b68a59df826310d2032eb6331aebc51f83f5c6921dfba5927984110b6b8bf61` | 程序替换并启动为 `0.1.1`，原工作区与草稿可读，收据为 `installed`。 |
| 新版后台无法启动 | 163,008,003 字节，`041fa06f20c38c779511377b4acd76215fb548c829ac9cdd2bb1a78da8a0ce7d` | 将测试包的后台入口改为立即退出再签名。新版未报告启动完成，安装程序在 30 秒后恢复并重开 `0.1.0`，收据为 `rolledBack`。 |

关闭重开后的两个原生窗口后，检查确认隔离桌面、安装程序与后台进程均已退出。正常安装后的实际包另外通过了官方 Node、原生 PTY、Hive HTTP/SQLite 和后台关闭冒烟。证据位于 `.artifacts/update-install-mac-GKtwbz/receipt.json`、`replay-v2.log`、对应隔离目录的 `old-desktop.log` 和 `post-install-smoke.log`。全程无模型调用，只操作隔离副本。
