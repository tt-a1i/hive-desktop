## 实现与限制

- 待发用户输入可以编辑或撤回；原投递 ID、顺序、图片、文件副本与来源保留。执行中、已尝试、已完成和协作投递不可修改。旧主控队列缺少准确的 Hive 消息身份时明确禁用，不能猜测重复文字对应的原记录。
- 主控输入使用 Hive 既有 SQLite 消息序号更新原始记录并记录编辑/撤回审计。撤回使用持久化标记，处理文件队列和 SQLite 提交之间的崩溃窗口；撤回或审计记录不进入恢复任务摘要。协调写盘失败会停止受影响的原生会话，重新加载和校对后才能继续。
- 全局、项目侧栏和归档搜索增加正文匹配、摘录与消息定位；按范围排序后分页。Pi/外部 Pi 读取当前持久化分支；Codex 完整原生分页成功后保存可验证的搜索快照，后续变化会使完整标记失效。完整表示最近一次同步保存的历史，不宣称监视外部 CLI 的所有修改。
- Claude 使用官方 SDK 的只读历史读取。SDK 不能可靠区分空历史、缺失与跳过的损坏行，因此明确显示完整性无法核实；旧 Codex 展示缓存也明确提示可能缺失。搜索不启动 Agent 或请求模型。
- 项目文件检索遵循 Git 忽略规则；非 Git 目录排除依赖和构建目录。引用保存经路径、文件句柄和大小/类型检查的 UTF-8 字节快照，持久化相对路径与 SHA-256。源文件修改或删除只改变状态提示，不替换已保存副本。上传、草稿、队列及历史继续复用现有附件契约。

## 真实 Codex Terra

执行 `packages/runtime/checks/functional-parity-native-codex.ts --live`，仅在隔离项目中使用原生 Codex 与 `openai/gpt-6.1-terra`。未修改全局模型或账号配置。

原始收据：`.artifacts/functional-parity/native-codex/receipt.json`。隔离数据：`/var/folders/v1/6vx82zzx32q7y_s1w4sx84j00000gp/T/hive-functional-native-cAlg0d`。

1. 真实工具执行 `sleep 45` 时排入两条请求。
2. 第一条带项目文件引用，修改其正文；第二条撤回。陈旧原文的再次修改被拒绝。
3. 停止并完整重启运行时，保留相同投递 ID、编辑正文、引用来源及副本，保持暂停。
4. 继续后原生 Agent 从源文件已删除的副本读出随机标记，写入 `result.txt`。独立文件读取核对完整字节为该标记加一个换行。
5. 编辑后的投递在原生历史只出现一次，撤回投递没有进入原生历史，`canceled.txt` 不存在。
6. 实际模型/工具输出可被正文搜索定位，收据中的历史不完整计数为 0。
