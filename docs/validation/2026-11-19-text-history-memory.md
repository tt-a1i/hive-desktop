# 长文字历史传输和桌面内存

桌面使用的历史快照保留完整显示正文、工具参数和原生补丁，只从原生消息对象取出其类型、编辑身份和中断状态。已保存的原生历史和默认 RPC 响应保持完整。显示行建立消息 ID 索引，快照恢复和增量更新可直接找到已有行。会话切换释放旧索引和正文。多段正文借用分段原文，再按最终长度分配显示字符串。

## macOS 实测

两个本地签名调试包打开同内容的 Pi 历史，包含 1,803 条原生快照记录。包内 JSONL 对比确认消息 ID 序列完全一致，显示字段的 SHA-256 一致。末尾可见并稳定后，各取五次桌面进程 RSS 的中位数。

| 观测项 | 基线 | 修复后 |
| --- | ---: | ---: |
| 会话打开响应 | 46,544,229 字节 | 23,414,512 字节 |
| 桌面进程 RSS | 222.2 MiB | 212.1 MiB |

中间版本逐段追加文本产生了额外容量，RSS 为 239.8 MiB。修复后用同一个持久化会话重新冷开，得到上表结果。新增 Rust 检查覆盖长首段、空段和短尾段，核对换行及缓冲区容量。

从空会话打开跨会话搜索，按工具输出正文命中长会话并定位到对应的早期工具行。展开后核对最终输出和工具参数。同一调用的旧输出已被更新后的输出取代。实际保存的 Markdown 大小为 22,421,463 字节，包含首尾消息、全部 1,798 条长正文的末尾标记、工具参数、最终输出和原生补丁。切回空会话再重开，恢复了原工具位置及展开状态，随后可以回到末尾。两版窗口均正常退出，后台确认关闭，记录的进程均已退出。

类型检查、图片附件及完整正文搜索专项通过。Rust 单测 116 项通过，1 项辅助入口按设计忽略。Windows MSVC 交叉检查通过，Windows 原生内存待测。测试使用隔离数据，未请求真实模型或发布。

当前桌面仍完整载入文字正文。本次减少的是打开响应里的重复数据和 Rust 分段合并的多余容量。详细数据与原生导出见 `.artifacts/text-history-memory-r8JKVt/` 下的 `receipt.json`、`wire/receipt.json`、双包退出日志及 `after/project/complete-text-history.md`。
