# Hive Desktop 实施方案

日期：2026-11-06。

状态：产品方向与 GPUI 界面路线已确认。正式 macOS 应用已接入内置 Pi、Codex app-server、外部 Pi RPC，并分别验证真实主控与 Worker 协作；完整应用尚未实现。本文记录实施顺序与接入边界，当前证据见 [进度](progress.md)。现有 Hive Web 协作能力已在用户使用场景中验证，桌面工作的重点是复用及新增接入层。

## 真实使用场景

1. 用户在 Hive 中安排多个 Agent 完成项目工作，希望在桌面统一聊天界面里使用自己偏好的 Agent 与模型担任主控，同时保留现有团队协作能力。
2. 完成后，用户可选择主控、发送需求、查看工具过程和 Worker 会话；主控通过 Hive 派单，Worker 显式汇报后，结果回到对应主控会话继续处理。
3. 不做桌面客户端，用户仍可使用现有 Web 协作，但缺少所需的桌面统一聊天入口及整合后的配置体验。

## 实现边界

### 协作业务

- 复用 Hive 现有团队、工作区、派单、消息、汇报与恢复规则。
- Hive 负责协作状态和消息路由；当前选择的主控 Agent 负责理解、决策、派单和汇总。
- 外部 Agent 担任主控时，不额外放置一个 Pi 负责转述或决策。
- 原生工具、MCP 或既有 `team` CLI 应进入同一套协作业务；具体接线根据后端选择。
- 保留现有显式汇报与确认语义，不把厂商的聊天回合结束事件等同于 Hive 任务完成。

### Agent 接入

| 后端 | 方向 | 尚需完成的工程工作 |
| --- | --- | --- |
| 内置 Pi | Pi SDK 1.4.0，不加审批流程 | 主控/Worker 真实协作已穿透，继续完善配置及生命周期体验 |
| Claude Code | 官方 Agent SDK 连接用户原生 CLI，已接入共享会话与原生界面 | 无推理控制、恢复和界面已验证；真实模型协作、活跃取消及权限交互仍待验证 |
| Codex | 原生 app-server 已接入 | 主控/Worker、流式工具、停止、整体恢复已验证；继续完善原生审批与用户输入交互 |
| 外部 Pi | 原生 RPC 与显式 Hive 扩展已接入 | 使用外部安装、认证、配置与扩展；主控/Worker、流式工具、停止和整体恢复已验证；扩展交互仍需完善 |
| 其他 Agent | 允许通过 ACP 或专用适配器扩展 | 逐个声明和验证实际支持的能力 |

统一的是 Hive 内部所需的会话操作和聊天事件，不要求所有后端提供完全相同的厂商功能。架构支持扩展，不宣称已自动兼容任意 CLI。

首版按由 Hive 启动和管理外部 Agent 会话组织实现；接管用户另外打开的终端不计入当前实施范围。

### 桌面与界面

- 首版必须支持 macOS 和 Windows；两个平台的构建与交互验证分别记录。
- 桌面 UI 采用 Rust、GPUI 与 gpui-kit，共用一套 macOS / Windows 原生界面代码；具体平台集成分别处理。选型依据见 [GPUI 调研与决策](research/2026-11-06-gpui.md)。
- Hive Node 后台继续承担协作、持久化与 Agent 接入；不因 UI 技术栈变化重写为 Rust。优先使用 gpui-kit 的输入、Markdown、列表和配置组件，将原生界面实现成本集中在产品需要的交互上。
- 桌面窗口连接 Hive 后台；会话、协作和持久化归后台管理，界面展示与执行生命周期分开。
- 首版即提供内外部 Agent 的统一聊天体验。
- 主会话、成员、工具过程和配置的具体布局参考 Cindy 等项目后落地，不要求用户先给出完整 UI 设计。
- 新增依赖和抽象以实现当前需求为限。

## 实施顺序

1. **锁定复用基线**：刷新 Hive 权威仓库，记录提交；盘点当前 Web 能力与配置，列出复用模块及桌面接入位置。旧 PR review worktree 不作为默认实现基线。
2. **建立桌面运行骨架**：确定后台启动、连接、窗口关闭、应用退出和重连行为，验证 Node/native 模块与外部 CLI 的发现和运行方式。
3. **落地统一聊天与首个 Agent 后端**：定义最小会话与事件契约，接入内置 Pi；保留原始后端身份及能力差异。
4. **接入外部主控与 Worker**：实现 Claude Code、Codex、外部 Pi 的选定接入方式，对接已有 Hive 派单与汇报链路；按实际需要增加 ACP。
5. **整合 Web 能力与配置**：依照功能清单迁移现有能力，参考现成项目完成成员、会话、工具与配置界面。
6. **验证桌面新增边界**：检查统一聊天、停止与恢复、后台重连，以及目标平台打包和真实 CLI 运行。

这些步骤是实施顺序，不表示当前已完成任何应用里程碑。用户已授权按完整目标持续实施，并明确不再追加选型测试；按 GPUI 路线进入桌面工程落地。平台构建、输入、打包和真实 Agent 验证纳入对应实现任务，不作为继续讨论技术选型的前置条件。

## 验收依据

- 最终标准是完整、精美且可日常使用的产品：聊天、配置、操作细节对标 Cindy / Maka，尤其重视后端逻辑正确性。骨架、单条闭环和构建通过均不代表完整交付。

- 真实模型测试统一使用 Codex 的 GPT-6.1 Terra（用户 2026-11-07 指定）。Pi 内置接入直接使用其 OpenAI / ChatGPT OAuth 提供方及 `gpt-6.1-terra`，不依赖 Magpie。只选择项目测试会话的模型，不改用户全局默认；遇到连接或账号问题保留失败证据，不改用其他测试模型。
- 现有 Hive Web 能力是迁移基线，已有业务语义保持一致。
- 内置和首批外部 Agent 均能担任主控或 Worker，并在统一聊天中显示消息与工具过程。
- 新接入路径能够穿透现有链路：主控派单 → Worker 执行 → 显式汇报 → 正确主控会话接收并继续。
- 用户输入、Worker 汇报和厂商回合结束分别处理；不凭聊天结束推断任务结算。
- 停止、重连和恢复按已有 Hive 规则及选定后端能力实现，明确不支持的行为。
- 关闭窗口与退出应用的行为需在桌面运行骨架阶段明确；不得把恢复会话与恢复任意中断中的工具执行混为一谈。
- 验证集中于新增接入与桌面运行边界，复用核心协议有改动时运行对应回归；界面以静态检查、构建和实际走查验证。
- 分别记录源码调研、实际集成运行、平台验证和安装包状态。
