# 桌面操作体验持续对标

目标是让用户在实际项目里少绕路。每轮从三个参考产品中找出能复现的操作差距，先修容易误操作、丢失当前状态或反复多点的地方。记录同一操作在 Hive 的修复前后表现，以及实际验证的平台。任务见 [#57](https://github.com/tt-a1i/hive-desktop/issues/57)。

## 接下来优先检查

- **跨项目收件箱的阅读顺序。** 用包含多条等待用户、等待 Agent 和后台错误的夹具，检查用户能否快速看出哪些必须现在处理，以及新事件插入时键盘或指针下的行是否改变。先验证等待用户和等待 Agent 的分组，再处理实时重排行为。 [Cindy 收件箱规则](https://github.com/makecindy/cindy/blob/86c473f9ecc9a4deeb8180bc21deb0416411d828/docs/product-rules/task-inbox.md#L34-L57)
- **文件面板回到工作树后的原位置。** 依次在两个工作树展开同名目录并选文件，返回时应恢复各自展开状态。接着验证从聊天或 Diff 能否在文件树里选中对应路径。 [Beluga 文件面板](https://github.com/beluga-labs/beluga/blob/45a484b616a274a886e55bc28c1879719351a7c1/packages/mac/src/layout/panel/FilesTab.tsx#L148-L213)
- **首次打开的项目发现。** 用多个真实结构的临时仓库验证，尤其是最近项目超过一屏、导入部分成功、退出后继续勾选的情况。先缩短从发现项目到开始聊天的操作，再评估无项目的临时会话。 [T3 Code 推荐与恢复](https://github.com/pingdotgg/t3code/blob/ccc1feb15572c422fbdce26ba6077b91459cfd47/docs/user/welcome-page.md#L65-L117)
- **发下一条消息时按次切换队列行为。** 在已有运行中验证，用户能否临时选择排队或引导而无需更改默认设置。保留后端能力限制与现有键盘发送设置。 [T3 Code 输入快捷键](https://github.com/pingdotgg/t3code/blob/ccc1feb15572c422fbdce26ba6077b91459cfd47/docs/user/keybindings.md)
