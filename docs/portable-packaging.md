# Portable development bundles

These are unsigned development bundles, not production installers. macOS bundles are not notarized. Build and package on the target operating system and CPU architecture; this workflow does not cross-compile or establish compatibility on another platform.

Install dependencies with `pnpm install --frozen-lockfile`, build the runtime with `pnpm build:runtime`, and build the native desktop executable. Then run:

```sh
pnpm --filter @hive-desktop/runtime deploy --prod --frozen-lockfile --node-linker=hoisted PATH_TO_NEW_RUNTIME_DIRECTORY
node scripts/package-desktop.mjs --executable PATH_TO_NATIVE_EXECUTABLE --runtime PATH_TO_NEW_RUNTIME_DIRECTORY --output PATH_TO_NEW_OUTPUT_DIRECTORY
node scripts/check-package.mjs --bundle PATH_TO_NEW_OUTPUT_DIRECTORY
```

The deployed runtime and output paths must not already exist. Run the deploy on the target OS and CPU immediately before packaging. macOS produces `Hive Desktop.app`; Windows produces a folder containing `hive-desktop.exe` and `resources`. Copy the whole app or folder together. The package includes Node 22.23.3 from the official Node distribution, verified against the official SHA256 list, its license, and the runtime's production dependencies. Node and dependencies must match the build host's platform and architecture. The check runs the bundled Node from a temporary directory, starts a real Hive host, creates a workspace without starting an orchestrator, checks shutdown and launches a real PTY; it sends no model request. The isolated PTY probe checks that its Node process exits naturally after the shell exit event. A Windows run observed shell exit but the probe process remained alive, with an active MessagePort and an additional PipeWrap. A platform-package patch closes the input socket and disposes the ConPTY output worker on the existing normal-exit cleanup path. Windows x64 CI run 42294650248 verified that both direct PTY and Hive agent-manager probes exit naturally, including a stopped run. The check does not validate native window behavior or external Agent installations.

The dependency deployment uses pnpm 10.30.3 `deploy --prod --frozen-lockfile` with a hoisted layout and `injectWorkspacePackages` enabled. The configured Hive patch is applied during deploy. An earlier development attempt used legacy deploy and re-resolved dependencies; that attempt is not the locked bundle.

Windows CI is configured to run the runtime-location unit tests, build and package the desktop, extract the final zip into a separate folder, smoke the extracted runtime and PTY, and upload that zip as an artifact. These are configured checks, not a claim that a Windows run has passed; consult the actual CI run for its result. A successful macOS check is not Windows validation.

Windows CI run 42284937037 passed native compilation and all four runtime-location tests but failed packaging while launching the pnpm Windows shim from Node. Running deploy directly in PowerShell resolved that packaging failure. Subsequent smoke runs found the PTY cleanup leak described above. Run [42294650248](https://github.com/tt-a1i/hive-desktop/actions/runs/42294650248) at `d694c5d` then passed the entire extracted-bundle smoke and uploaded the portable zip: direct PTY, actual Hive agent-manager natural exit and stop, HTTP/SQLite and owned runtime shutdown. The direct probe's resources settled to its two output PipeWraps and it exited naturally. This verifies the patch on Windows x64 CI, not native GUI behavior, ARM64 or model execution.

External Pi and Codex use `cross-spawn` to resolve Windows npm/pnpm shims and quote their arguments, including installation and workspace paths containing spaces. Protocol input/output remain pipes. Closing a process first ends stdin; on Windows a timed-out live owned root is terminated with `taskkill /T /F` and its close is awaited. Arbitrarily killing the wrapper from outside Hive can leave descendants after its PID disappears; this implementation does not claim to recover those descendants.

After the extracted bundle smoke, CI installs official Pi 1.4.0 and Codex 0.166.0 in a directory containing spaces. The dedicated check initializes their real RPC/app-server controls through PATH and explicit `.cmd` paths, queries state/catalog, verifies native Codex `.exe`, and observes actual child-exit and awaited cleanup. It never sends a model prompt. A separate synthetic stubborn Node tree checks forced tree termination. The receipt distinguishes those scopes. The Windows results remain pending; local macOS control checks only establish that the shared launcher preserved the existing Mac paths.

Claude sessions always select the user's original CLI explicitly. The workspace therefore excludes the SDK's eight precisely named optional native CLI packages through pnpm's `ignoredOptionalDependencies`; it retains the SDK itself and other platform dependencies, including node-pty. No vendor files are manually deleted and `--no-optional` is not used. A scratch frozen install/deploy without these binaries passed actual external Claude controls, hidden-context resume, shared runtime recovery, and the Mac package's real PTY/Hive/HTTP smoke without inference. The removed Mac ARM64 executable alone was approximately 298 MiB. The candidate app occupies approximately 612 MiB, but comparison bundles used different native builds, so this is not a controlled whole-package size benchmark. Evidence: `.artifacts/claude-optional-candidate/.artifacts/claude-runtime-vY1DSv/receipt.json` and `.artifacts/claude-optional-candidate-bundle`. Windows must validate this dependency selection independently.
