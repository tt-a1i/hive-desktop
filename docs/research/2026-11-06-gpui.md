# GPUI 桌面技术栈调研与决策

日期：2026-11-06。决策：采用 GPUI + gpui-kit 构建 macOS / Windows 桌面界面，继续复用 Hive Node 后台。源码与官方文档已核对，macOS 独立原型已编译运行并完成真实后台只读连接。用户明确要求停止追加选型测试，进入产品实施。未作性能对比，也未验证本应用 Windows 运行与安装包。

## 成本权衡

GPUI 的 GPU 渲染和无需 Chromium 的界面架构符合本项目的响应与资源占用方向；生态已有跨平台实现及常用组件，当前未发现必须放弃这条路线的障碍。性能方向支持采用，不等于已证明完整 Hive 的性能指标。

新增成本主要是 Rust 原生视图、桌面打包和平台交互适配。通过保留已验证的 Node 协作后台、共用两端 UI 代码、固定 GPUI / Kit 兼容版本、优先用现成组件控制成本。Cindy 等项目继续作为聊天与配置体验参考，Maka 作为运行时组织参考。暂不引入 Maka 的多套原生渲染后端。

## 对 Hive 的影响

GPUI 可作为 Rust 桌面界面，使用 HTTP/WebSocket 连接已有 Hive Node 后台。内置 Pi、外部 Agent 接入和协作规则继续由后台管理，选择 GPUI 不要求把协作底座重写为 Rust。

现有 React/Tailwind/Radix 组件不能直接作为 GPUI 原生组件运行。业务能力和接口可以复用，聊天、配置、成员及终端的显示与交互需要实现对应原生视图。现有 Web 客户端继续维护时，两套界面都需要维护。

## GPUI 当前能力

- 官方 GPUI 支持 macOS、Windows、Linux。macOS 使用 Metal；Windows 使用 Win32/DirectWrite；Linux 支持 Wayland/X11。
- GPUI 仍处于 pre-1.0，官方提示版本间可能存在破坏性变化，使用时应固定相互兼容的版本。
- Longbridge 的原 gpui-component 项目现为 gpui-kit，提供输入、Markdown、代码展示、虚拟列表、布局与可访问性能力，有流式 Markdown 示例。
- gpui-kit 当前清单锁定 GPUI snapshot，并提供 runtime_shaders 特性；实际 Rust/Xcode 构建要求需以所选版本验证。
- GPU 渲染可改善界面绘制路径，但不能据此推断模型响应、外部 Agent 执行更快，或带 Node 后台的 Hive 整体内存一定更低。当前原型有进程快照，尚无同功能、同负载对比。

## 已完成的有限验证

- 官方 crates.io gpui-kit 0.9.0、gpui-pre 0.3.11、Rust 1.98.0；macOS arm64 编译并打开原生窗口，采用标准 runtime_shaders 路径，无第三方补丁。
- 实际窗口已观察中文多行粘贴与编辑、演示 Markdown / 代码块流、成员选中状态，以及真实 Hive `session → workspaces` 只读请求返回 200 / 空列表。
- 最近一次 debug 原型 RSS 快照约 132.8 MiB，隔离空 Hive Node 后台约 55.7 MiB，合计约 188.5 MiB；不含外部 Agent，不能当作最终产品预算或与 Electron 的性能比较。
- Windows / macOS 构建工作流已编写，尚未在远端运行；Windows 原生交互、真实 IME 组合输入、完整 Agent 会话、超长会话性能和安装包未验证。

详细复现与范围见 [原型收据](../../experiments/gpui-chat/VALIDATION.md)。这些边界进入实现验收，不继续扩大选型实验。

## Maka 实际进度

本轮查询的 main 为 `b511478d0a01d2a20437a56cd435ab71a6cb2815`，仍是之前研究的 TypeScript 主线。

Rust 预览分支快照为 `500d53b46b4e8857bdb8b438e364488bd9b122f4`，桌面 shell 已采用混合平台后端：

| 平台 | 预览分支当前默认路径 |
| --- | --- |
| macOS | NSH AppKit；可通过 MAKA_GPUI 选择 GPUI |
| Windows | NSH Direct2D |
| Linux | GPUI |

该分支使用带自有补丁的 GPUI Fast。不能将它概括成已完成的全平台纯 GPUI 重构。

PR #6674 提议进一步替换 GPUI、Linux 使用 GTK。本轮 API 状态为 open、draft=true、merged=false，目标分支 rust-preview，head 为 `0c09de1584b4388802adf957ad3d0afc4ef4b221`。PR 说明最终变基后的检查未全部重跑，macOS/Windows GUI 与部分 Linux 交互验收未完成。这是候选改动，不是已发布结果，也不足以单独判定 GPUI 优劣。

## 实施时处理的界面边界

按 GPUI + gpui-kit 落地实际产品，在对应功能开发时处理：

1. 中文输入法组合、候选框、多行编辑、快捷键与粘贴。
2. 流式 Markdown、代码块、变高长列表、滚动定位及文本选择复制。
3. 主会话与成员视图切换、工具事件和已有协作状态展示。
4. 窗口关闭/重连与后台生命周期；保留现有恢复语义。
5. 辅助终端的实现成本，以及目标平台构建、输入和安装包验证条件。

测试数据需区分 UI 测试流与真实 Agent 输出；只完成测试流或编译不能作为协作接入完成。GPUI 选型已收敛，后续验证用于交付真实功能与目标平台体验。
