# Hive native desktop

Actual GPUI application backed by the Node runtime, separate from the UI selection experiment.

From the repository root, build the runtime using `pnpm build:runtime`, then:

```sh
cargo +1.98.0 run --manifest-path apps/desktop/Cargo.toml
```

Development uses `node` from PATH and the runtime from the repository root derived from `CARGO_MANIFEST_DIR`. Portable bundles locate their own Node/runtime relative to the executable and add bundled Node to the child PATH. `HIVE_DESKTOP_NODE` and `HIVE_DESKTOP_RUNTIME` remain explicit overrides. External executable resolution uses `HIVE_CODEX_COMMAND` / `HIVE_PI_COMMAND`, then the app's external-program settings, then PATH. Saved changes apply to new processes and never modify agent-global configuration. Each external-program row can run a bounded `--version` check on the current draft, respecting environment overrides without saving it. Results show the actual tested command and version; differing verified versions are informational compatibility limits, not automatic upgrade requirements. Checks are cancelled and awaited during runtime shutdown. See [program checks](../../docs/validation/2026-11-08-executable-check.md). Verified macOS versions are Codex CLI 0.167.0 and Pi 1.4.0; Windows CLI checks retain their separately documented version and acceptance scope. See [portable packaging](../../docs/portable-packaging.md); these unsigned development bundles are not production installers.

Workspace creation calls Hive's real API with `autostart_orchestrator: false`. Create a conversation with builtin Pi, external Codex, external Pi or Claude; each retains its own backend identity and native session. Chat history, model availability, prompts, cancellation and streamed tool output come from that backend. User messages render literally; assistant messages use Markdown. No demo conversation or model request runs automatically.

Closing the window or pressing Cmd/Ctrl-Q sends `shutdown` and awaits cleanup of the owned sidecar scope: a private process group on macOS and a Job on Windows. It allows three seconds for graceful exit before terminating that scope; cleanup failure retains the window and original owner for retry. macOS processes that intentionally leave the group are outside this confirmation boundary. Active builtin Pi shells additionally watch their Node owner and clean their detached group on owner exit; that asynchronous cleanup is documented separately in [shell ownership](../../docs/validation/2026-11-08-pi-shell-owner.md). The OS final-quit fallback uses zero grace and is best effort because GPUI limits quit observers to 200 ms. See [supervision evidence](../../docs/validation/2026-11-07-sidecar-supervision.md) for platform results and remaining limits.

Current surface: local workspaces, four structured backend integrations, pending delivery resume, collapsible tool details, collaboration overview, role templates and member create/rename/start/stop/delete controls. Starting a member requires an explicit provider/model. Builtin Pi, external Pi and Codex have real team dispatch/report and nonempty history restoration evidence. Claude uses the original native CLI through its official SDK; native controls, shared-session persistence and the UI are checked without inference, while real Claude collaboration remains unverified. Its executable setting uses `HIVE_CLAUDE_COMMAND`, app settings, then PATH. Unsupported approval and user-input requests fail visibly; the adapters never automatically accept them. External Pi dialogs without a responder are cancelled. The existing window can manually restart a failed backend while retaining drafts and unsaved configuration; see [backend recovery](../../docs/validation/2026-11-08-backend-recovery.md). Settings polish, Windows native interaction and production installers remain separate work.

Conversation history now uses variable-height virtual rows, including individual tools inside expanded groups. Current-conversation content search, cross-project session-name search, session renaming and persisted system/light/dark appearance are available. A separate global pinned section exposes conversations across projects even when project lists are collapsed or unloaded; it supports direct switching, refresh, collapse and unpin. Search, project rows and pinned rows share the same guarded navigation flow. See [global pin validation](../../docs/validation/2026-11-08-global-pins.md). Session row menus support durable pin/unpin without opening another conversation; pinning preserves the activity timestamp and draft, and failed saves retain the original state. See [session pin validation](../../docs/validation/2026-11-08-session-pins.md). Every project row has its own Agent creation menu; collapsed projects summarize known conversation attention/activity and expand on selection. Project-specific creation preserves separate drafts and uses the existing creation/open flow; see [project navigation validation](../../docs/validation/2026-11-08-project-navigation.md). See [virtual-list validation](../../docs/validation/2026-11-08-virtual-conversation.md) for measured scope and pending physical interaction checks; these surfaces are not a claim of Cindy-level product completion.

On macOS, Windows target typechecking additionally needs LLVM's `llvm-rc` on the command's PATH. With the `x86_64-pc-windows-msvc` Rust target installed, run `PATH="$(brew --prefix llvm)/bin:$PATH" cargo check --locked --manifest-path apps/desktop/Cargo.toml --target x86_64-pc-windows-msvc` from the repository root. This checks the real application's default features, including its Windows manifest, but does not link an exe or replace native Windows validation. See [cross-check evidence](../../docs/validation/2026-11-08-windows-cross-check.md).

Session row menus also archive idle conversations without stopping their Agent or deleting history. Archived conversations remain searchable through 已归档, with paging and refresh. Current drafts and image attachments survive archive/restore; meaningful new deliveries restore navigation automatically. Pending messages and unsettled team dispatches block archival. See [archive validation](../../docs/validation/2026-11-08-session-archives.md).

Native thinking content is shown in collapsed disclosure rows separately from the final answer, including streamed updates and recovered history. Open a row to select/copy its text; conversation find reveals matched blocks. Explicit redactions show only an unavailable label. No reasoning content or timing is synthesized. See [thinking validation](../../docs/validation/2026-11-08-thinking-display.md).

Built-in/external Pi expose native per-session reasoning levels beside the model picker. Options come from the current native model, and changes preserve global defaults. Failed native configuration writes pause/dispose the affected handle before a retry can reload durable state; model changes share this recovery path. Codex/Claude now expose native advertised effort levels and applied-value readback. Their explicit choices are saved per model in the existing chat index and replayed on reopen; failed replay leaves readable history but blocks sending until repaired. Paginated Codex history retains native item IDs. See [external reasoning validation](../../docs/validation/2026-11-08-external-reasoning.md).

Settings → 内置 Pi lists SDK provider capabilities and saved-credential metadata, with search. Choose subscription sign-in or native API configuration; multi-step secret/text/select prompts and cancellation use the SDK. Removing saved credentials requires native confirmation and affects the shared Pi store (`PI_CODING_AGENT_DIR` is respected); environment and other auth sources remain intact. Session model choices remain independent of global defaults. Settings → 模型与接口 edits common custom-provider/model fields in Pi models.json, preserving JSONC comments and advanced fields. Stale external edits retain the draft and require rechecking; provider removal retains credentials and history. External agents retain their own authentication. See [model configuration validation](../../docs/validation/2026-11-08-pi-model-config.md). Run `pnpm --filter @hive-desktop/runtime check:pi-auth` for isolated SDK persistence, native API handlers and production JSONL checks without vendor or model requests. See [provider validation](../../docs/validation/2026-11-08-pi-provider-config.md) and the earlier [OAuth validation](../../docs/validation/2026-11-08-pi-accounts.md) for evidence and pending real-account/platform checks.

The composer supports local PNG/JPEG/GIF/WebP selection, clipboard images/copied image files, file drops, thumbnails, removal and image-only messages. BMP/TIFF clipboard images normalize to PNG; supported originals keep their bytes. Thumbnails open a full-image dialog with fit/original-size display, copy and atomic Save As. Drafts retain immutable workspace upload references across sessions/restarts; accepted delivery history renders thumbnails from original image blocks. Sending goes through the existing Hive user-input path and durable queue for all four adapters. Builtin/external Pi reject known text-only models before user history/HTTP. Exact upload bytes, failure retention and restart behavior are checked with real Hive/SDK and synthetic model peers; real Terra inference is currently blocked by an expired OpenAI OAuth grant. Physical file-picker interaction and Windows GUI remain unverified. General files, animated-image playback, physical Finder/native-save dialogs, long-image-history resource measurements and Windows clipboard/GUI acceptance remain pending. See [image input validation](../../docs/validation/2026-11-08-image-input.md) for the reproduced GPUI drop-after-keyboard fix, source override and native/synthetic evidence boundaries. See [image attachment validation](../../docs/validation/2026-11-08-image-attachments.md).

File attachments share Hive's existing workspace upload records and durable user-input/queue association. The attachment picker and file paste/drop accept ordinary files alongside images; ordinary files are referenced by their saved local copy and read on demand by the selected agent. Draft/history cards retain names and sizes and can reveal a copy in the system file manager. Original Codex Terra has read a copy after source deletion; native Pi/RPC local-rejection checks and Claude SDK synthetic-peer checks have separate evidence. Enter now uses the input component's native submit mode, preserving exact message text while Shift+Enter inserts a newline. See [file validation](../../docs/validation/2026-11-08-file-attachments.md).
